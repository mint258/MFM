# 工作方式

## 工作树、执行与版本

明确实际执行环境、checkout、任务分支及输出根。远程挂载是 live 文件系统，
编辑会直接修改服务器；名称相同的本地副本不自动同步。
Linux 项目使用服务器环境，不因可从客户端看到文件就用客户端解释器执行。

保持逻辑 Python/venv 启动入口；解析后的二进制目标仅作诊断。
同一二进制经不同 venv 入口可能选择不同依赖。批作业不假设继承登录 PATH。
实际依赖版本与目标 GPU 的完整模型兼容性应在对应环境核对。

冻结/活动源码、配置和清单不原地修改。新候选用独立版本/工作树，
保留执行 SHA、公开 SHA 与数据引用，不手抄终端重绘输出中的哈希。
修复工具不改变科学函数/版本/种子/输入，不重算已闭合结果来补日志。

## 调度与资源

正式或大批计算走站点既有 Slurm，先检查现有同任务，避免重复提交。
一个协调者拥有实际提交权；若当前任务另获并行 agent 授权，各工作者使用
独立范围，协调者整合。历史任务里的并行要求不自动要求每次工作都派 agent。

CPU/GPU 角色、节点例外、最少 CPU 数、内存、墙钟和存储策略都按任务范围核对。
数据线 CPU-only；模型线 GPU 用于实际 GPU 实验。已授权自动内存的开发任务
不声明固定 Slurm 内存，但默认 ReqMem=0 不是物理内存保证。
现场核对 CPU 分配、实际 RAM/RSS、设备 UUID 和活动进程。

队列空、节点 IDLE、显存空都不等于已预约 GPU。站点若未登记 GRES，
CPU allocation 不能称 GPU 隔离；保持已约定公共 UUID 锁、实际 GPU 进程
检查和显存余量。共享风险例外仅适用于获明确授权的任务。
不能为了腾资源修改、取消或抢占其他用户及不相关作业。

生产数据任务优先合并为日级父作业，内部用进程池和持久检查点，不为每个
分子/小批创建 sbatch。实际站点 MaxTime 仍存在；用户取消人工时限不代表
可以改变站点限制。任务专门取消的时限/失败门不应从旧模板重新引入。

## SSH、脚本与退出码

使用安全认证和主机验证，不把凭据写入技能、仓库或命令历史。
端点、用户、实际 UID、项目根一起确认；不同集群可能同叫 sonmi，
同名节点和同号 job 不能跨集群混用。

复杂远程命令优先写成自有脚本，以参数数组调用，避免多层 shell 引号失真。
非交互子 SSH 不需输入时用 -n，非交互 srun 使用 --input=none；
需要 stdin 的传输/脚本必须保留输入，尤其 rsync --protect-args 的 SSH
不能加 -n。不要把 JSON 序列化当 shell 转义。

Slurm 脚本检查 LF 字节，语法通过不代表 sbatch 接受 CRLF。
在执行命令的同一层立即保存退出码，再做日志和查询；缺失退出码不是成功。
若科学输出已闭合但外围会计查询失败，保留原 FAILED 父状态，
可独立补管理元数据，不因此重跑科学。

## 状态与恢复

区分“已实现、已提交、运行中、部分关闭、科学验收、模型验收、归档、在线同步”。
Slurm C0 只说明相应父作业的退出，不说明全部目标完成；正常 partial 不是 FINAL。
squeue 旧 ID 消失不等于需要重跑，用已留存 sacct 和闭合产物核对。
监控可见的文件长度/mtime 可能被共享文件系统缓存，不能据此取消或重复提交。

恢复绑定原源码/协议/配置、数据角色、种子/RNG、优化器、采样游标、
持久 checkpoint、历史指标与 lineage。保留原失败和弃置尾部，不能伪称无损，
不能从未持久的日志尾部重建规范曝光量。实际已完成的样本不重复计算。

对本次自有进程发信号前，核对 PID/UID、boot ID、内核 start_ticks、
argv、进程组/cgroup 与 Slurm 身份；墙钟创建时间仅作诊断，
NTP 漂移不替代稳定生命周期。禁用宽泛 pkill/killall。
暂停/清理权限来自当前任务，不能按历史 PID 或旧删除许可操作。

活动 SQLite 的进度观察优先小日志或 OS 元数据，不做全表 COUNT/GROUP BY
给写者加长读锁。完整查询放在已关闭数据库或独立闭合副本上。
异常 sstat 数值、不可达计算节点 sacct 都是观测问题，不是零成本或科学失败结论。

## 实验记录与成本

保持持久实验记录：配置、种子、源版本、数据/划分、step/曝光量、
主要 loss、逐字段有效数、验证指标、耗时、吞吐、内存和 checkpoint。
W&B 离线可用时如实标 offline；SDK 返回和 journal fsync 不证明原生历史已落盘，
离线归档不等于在线同步。未同步记录不当缓存随便删除。

保留原 SDK、指标表、曲线、来源清单和命名明确的阅读入口。
正在写入的 run 保留原地，终态后归档；失败也保留。
模型线最新非阻塞修订见 DECISIONS，不重新制造逐作业审计门。

分配核时使用唯一父作业 AllocCPUS×ElapsedRaw，包含失败、前置和修复，
不重复加 batch/extern。GPU 节点分配时长不冒充 GPU 利用时长。
未知 accounting 不填零；各阶段/范围成本分开。

## 配额与清理

每个账户/挂载域单独读取真实 user quota，保留单位与原始读数。
soft/hard=0 表示未设置该类限额，只对正限额取有效上限；
额度未知时不以整盘 df 安排大规模输出。
另查整盘容量、inode、节点 scratch 与所有并发未来预算。
新旧原子写入、pending、失败、归档和临时副本都计峰值，不双计父子目录。

统计区分表观大小、实际分配块、虚拟 map 大小；du -b 已表示表观大小，
不能用两次表观 du 的差证明稀疏文件节省。
完整排名必须等待扫描终态，部分已知目录不能称全局最大。

删除先核对具体解析路径、所有权、活动/恢复依赖、保留价值和当前授权。
仅有明确冗余证据的已结束临时产物可在授权内清理；不能按文件年龄删除。
原始数据、唯一结果、活动 checkpoint、未同步 offline run 和重要失败证据保留。
同配额内移入垃圾箱不算释放；Windows 删除不跨 shell 拼接路径。
历史 alpha/unimol 或 D3 旧版清理许可均已消耗，不形成未来通用授权。

## 报告、Git 与维护

文档足以写方法/补充材料：目的、输入身份、规则参数、脚本统计、异常、
限制与负结果。一次交付只做当前要求的必要检查，不反复复制相同审计层。
按最新任务政策写同一每日摘要；原始证据保持可追溯。

提交前运行仓库检查器，保留旧 source manifest。新知识/技能改动
不重写科学源，不携带重资产或认证。后续用户修订在对应主题记录范围和
替代关系；状态附日期和来源，临时队列/空闲量不写成永久规则。
