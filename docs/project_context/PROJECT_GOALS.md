# 项目目标与两线分工

## 研究问题

构建受控实验系统：在相同分子、构象、架构和可比训练暴露量下，比较结构
自监督 S、描述符 D、额外物理标签 P 的下游贡献、互补与冗余。
不预设 P、SDP 或完整模型必然获胜；负结果不能自动解释为工程故障。
历史 ADMET/fusion 结果是另一表示与评价体系，不能冒充 H0 控制实验。

当前准备目标是冻结模型 v3、训练代码与配方，为后续构象网格及 S/S′、
P/P′ 对比提供基础。后续科学实验与正式预训练依其单独授权推进。

## 模型线

分支 model-v3，核心 current/phychem_mfm，报告 docs/model_v3。
目标主干为 6 层×512 维，H0 接口固定。任务书“约一千万参数”为粗估；
原阶段 0 实测主干 12,709,424、含 A4 完整模型 22,352,859 参数。
旧 4×384 是独立历史基线。

| 阶段 | 交付与实际验收 |
| --- | --- |
| 0 | 代码与参数基线 |
| 1 | 目标硬件上的性能拆解 |
| 2 | 等价性、数值轨迹、bf16、实际吞吐 |
| 3 | 实际载荷、逐头过拟合、损失与恢复 |
| 4 | 冻结 TRAIN 内层开发面板、评估器与端到端整合 |
| 5 | 按预注册规则选择架构、视图、预测头 |
| 6 | 配方与样本预算 B*，用户确认具体结果后冻结 |
| 7 | 配置、代码标记、交接、真实冒烟，PR 由用户合并 |

本阶段不做最终 TEST 选择、完整外部基线、正式预训练或未经授权的构象网格。
真实 D-3 未验收时可开发现有 S 和明确标记的合成路径，不能伪造字段或交付。

## 数据线

分支 data-v1，优先定稿既有 v1，再准备 PubChem v2 候选。
数据线使用 CPU，保持模型代码和原始 LMDB/WP5 权威数据不变。

| 交付 | 内容 |
| --- | --- |
| D-1 | ID、角色、几何、字段、形状、单位、掩码、精度、顺序、版本契约 |
| D-2 | 标签注册表、家族、物理类型、有效性与损失政策 |
| D-3 | 固定 50,000 TRAIN＋5,000 ROUTINE VAL 试点导出 |
| D-4 | 与人口/掩码绑定的 TRAIN-only 元素参考与归一化 |
| D-5 | 嵌套分子子集、已见分子未见构象诊断集 |
| D-6 | 最终 v1 全量导出与节点分发；整理日仍暂停 |
| D-7 | 构象数、固定随机/能量/多样性顺序及统计 |

数据侧验收与 Model payload ACK 分开。字段学不会时两线一起检查标签、
载荷和模型，消费方不能静默修正标签。科学接口改动须版本化和明确沟通。

PubChem 第一批默认 250 万，R/N 各 125 万；先定累计 1,000 万的嵌套队列，
只计算第一批。只做 UFF 和 D，不做 PM7、xTB、P′ 或训练。
最新每分子最多 3 个真实构象，见 DECISIONS，不沿用旧 10 个及补足规则。

## 责任与证据

数据线主要维护 workflows/data_v1_final、workflows/expansion、
configs/data_v1、docs/data_v1、docs/expansion 和接口目录。
模型线维护模型/训练代码、配置与报告；接口共享但不相互代签。

Git 保存代码、配置、小型报告与来源清单；大型载荷、完整日志、权重、数据库在外部。
冻结代码、协议、失败和历史验收保留，不通过覆盖它们表示新结果。
