# 基准测试线补充指示：启动 B0、B1、C1、B2 环境准备与下游构象预生成（用户 2026-11-18）

适用：下游评测与基线对比（`docs/benchmark/BENCHMARK_PLAN.md`）。用户接下来约一周不看具体进度，本指示授权下面几项工作，执行中不再等待用户确认。

其余规则沿用 BENCHMARK_PLAN，包括：
- §2 适用域与任务去留规则；
- §4.5 泄漏检查；
- §7 停止条件；
- §8 不做清单。

## 1. B0：数据准备

照 BENCHMARK_PLAN §5 的 B0 执行：
- 下载 §1 的全部候选数据集；
- 按 §2.1 过滤，输出过滤前后的数量表，按原因分列；
- 盲测榜单不过滤，照 §2.1 处理。

额外报告 pKahub 的标注情况，供用户决定 §6 第 1 条：宏观和微观 pKa 各有多少记录，多电离位点分子有多少个。

## 2. 下游构象预生成（S′ 和 S）

范围：通过 §2.1 过滤、且**没有数据集自带参考构型**的下游分子（§2.1 第 5 条）。自带参考构型的数据集用参考构型，不另外生成。

- **S′ 构象（UFF 几何）：**
  - 用预训练 S′ 的原流程：`sprime_v6.py` 的科学参数，RDKit 2025.09.5，ETKDGv3 加 UFF，0.5 Å 去重；
  - 每个分子最多 3 个实际构象，与 PubChem 扩充数据一致；不补足，不做科学重试；
  - 单分子累计 3600 秒硬截止。
- **S 构象（PM7 优化几何）：**
  - 以每个 S′ 构象为起点，用预训练 S/P 数据的同一 PM7 优化流程（MOPAC 版本、关键词和收敛设置沿用预训练数据线）。
  - 先从仓库和服务器记录里恢复这套流程。**找不到可复现的原配置时，不自行拼一套**：只交付 S′，在日报"待用户决定"记一行。
- 两套构象按分子和构象 ID 一一对应，保留源原子顺序。这是唯一需要核对的地方：每个 S 构象指向它的 S′ 起点。
- 所有 3D 基线和我们的模型都用这套构象（§4.4）。构象定下后就不再更换。

## 3. B1：传统基线和任务名单

- 照 §5 的 B1，在全部候选任务上跑三个传统基线，按 §2.2 定最终任务名单，在日报里报告名单。
- **pKa 和 NMR 两个任务**暂不跑基线，等用户回答 §6 的两个问题（pKa 的任务形式；NMR 采用哪个标准划分）。
- B0 里给下游分子算 P/D 标签那一项照 §5 执行。P 标签依赖第 2 节的 S 构象；S 构象交付不了时，只算 D 标签和 P′（UFF 单点），P 记为待定。

B2 及以后（提取冻结表示、预训练基线、我们的模型）本次不启动，只做下面 3a、3b 两项。

## 3a. C1：标签当特征（2026-11-18 追加）

- 照 BENCHMARK_PLAN §3.1a 的 C1 执行。B0 算出下游分子的 P/D 标签后，喂给 LightGBM 和 TabPFN，分三组特征：P、D、P+D。
- 原子级任务用原子级 P 字段（电荷等）加 RDKit 原子特征，只接 LightGBM。
- 划分、指标、超参协议和 B1 的传统基线完全相同，用默认或文献配置，不搜参。
- TabPFN 超出样本或特征上限时，按 BENCHMARK_PLAN §4 的子采样集成方式运行，并标注出来。
- P 标签计算失败的分子，在 C1 中按缺失处理，不填补。
- S 构象交付不了、P 标签待定时：先只跑 D 组，P 组和 P+D 组等 P 标签有了再跑。
- pKa、NMR 照第 3 节，等 §6 的决定。
- 只跑 1 个种子。只用 CPU；TabPFN 可短时用空闲卡。

## 3b. B2 环境准备（2026-11-18 追加）

对象：
- §3.1 的预训练基线：TabPFN、Chemprop v2、CheMeleon、MiniMol、Monroe、Uni-Mol、MACE-OFF、UMA-S；
- §3.2 的推荐基线。

每个模型做三件事：
1. 搭好独立环境，记录版本或 commit；
2. 核实权重是否公开、能否下载和加载，记下权重来源和许可；
3. 在固定的 100 个下游分子上跑通推断（从第 2 节的构象里按 seed 20261025 抽取，3D 模型用 S 构象，S 未交付时用 S′），记录输出维度。

规则：
- 每个模型的结论记一行，写进 `docs/benchmark/BASELINE_AVAILABILITY.md`：可用 / 权重未公开（照计划直接不用）/ 需申请权限。
- 需要账号或权限申请的（如 UMA-S 的 HF 权限），列进日报"待用户决定"，不代为注册账号。
- 跑通推断就是验收，不另做检查。
- 环境搭建和下载只用 CPU 节点。推断只用 CPU，或短时用空闲卡。

## 4. 种子数

全项目统一：最多 2 个种子，没有争议的只跑 1 个。
- 传统 ML 照原计划只跑 1 个种子，随机性由交叉验证覆盖。
- §4.3 的"每个配置 2 个种子"改为"最多 2 个"。什么情况下补第 2 个，在 B3 开始前另定。

## 不做清单

- 除 3b 的环境准备和 100 分子推断外，不启动 B2 及以后的阶段：不提取全量表示，不做读出或微调，不做任何预训练。
- 不占用配方线、head 类型线、任务解耦线正在使用的显卡。Chemprop 只用空闲卡或 CPU。
- 不用 GPU 的任务只在 CPU 节点 compute-0-8 ~ compute-0-19 上提交，不占 GPU 节点的 CPU（见 AGENTS.md 2026-11-18 规则）。
- 不改适用域规则、任务去留规则或划分，不根据结果调整任务名单。
- 不为 3D 模型另外生成构象；不对构象或标签做二次读回。
- 不删除任何文件，不用付费服务器。

沿用 BENCHMARK_PLAN §7。其他情况记一行日志继续。

成本超过估计 1.5 倍不停，在日报和周成本里报告。诊断或修复超过 4 小时、或连续失败 2 次，标为 UNRESOLVED，采用保守默认继续。
