# 时间盒规则修订（用户 2026-11-25）

适用：所有工作线。本文件取代各 TASKBOOK、USER_DIRECTIVE、AGENTS.md 和 `.agents/skills/mfm-*` 中"单项诊断或修复累计超过 4 小时，或连续失败 2 次，标为 UNRESOLVED"这一条。其余规则（包括停止条件、基础设施故障直接修复重跑）不变。

## 1. 失败分两类

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 工程失败 | 调用参数或接口写错、漏传参数；路径、权限、目录范围检查；存储额度或 storage guard 拦截；调度或准入拒绝、节点 drain、作业被杀；进程监控竞态；OOM；文件系统或网络抖动 | 修好重跑，从最近的完整断点或已保存的游标续接，日报记一行。**不计入失败次数，不能据此标 UNRESOLVED** |
| 科学或方法失败 | 新方法照设计实现后，在真实数据上仍不工作（例如真实 loader + 逐头过拟合验收不通过、训练数值发散、拟合不收敛）；输入数据本身缺失，或 ID/几何/标签无法对齐 | 计入时间盒（第 2 节） |

一时判断不了类别的，先按工程失败处理一次；同一现象再次出现时再归类。ID/几何/标签对不上时不猜，照原规则报告。

## 2. 时间盒

- 只对科学或方法失败计数，而且只对**同一根因**计数：同一根因修复 2 次后仍失败，标 UNRESOLVED。修好一个根因后出现另一个根因，重新从 0 计数。
- 4 小时只算诊断和修复本身的时间，不含排队等待和正常计算时间。
- 标 UNRESOLVED 时，日报写明根因和类别。根因属于工程类时不得标 UNRESOLVED。
- 标 UNRESOLVED 后的保守默认照原任务书（该臂记缺失 / 按未胜出处理 / 退回原头），主线继续。

## 3. 存储额度不足

storage guard 因额度不足拒绝或暂停任务时：

1. 先释放本线已结束任务登记的未用 future 预留（只改登记，不删文件）；
2. 仍不够：在日报"待用户决定"里写一行还差多少字节，任务保持等待或可续接状态。这不算失败，不标 UNRESOLVED。

删除文件仍是停止条件。

## 4. 已有的 UNRESOLVED 项

过去按旧规则标为 UNRESOLVED、但根因属于工程类的项，恢复为待完成，按原注册设计补做。已经按原规则完成的科学判定不重开。

- 配方线：A5，见 `docs/p_recipe/USER_DIRECTIVE_20261125.md`。
- D 线：L2 全 TRAIN A1 与 D-L2、D-R1 F64 几何诊断，见 `docs/d_recipe/USER_DIRECTIVE_20261125.md`。
- 其他线：自查本线标过的 UNRESOLVED，工程类的同样补做，日报各记一行。
