# 跨线指示：统一的节点与共享存储保护（用户 2026-11-22）

适用：所有在集群上写盘或占内存的线（P、S、D、D 数据、基准、基准数据、PubChem 扩充、各侧线）。与各线已有的存储准入写法冲突时以本文件为准。保留值、停止条件、集群规则不变。

目的：不让任何节点因为根盘、/tmp 或内存被写满而挂掉，同时不让保护本身拖慢工作。

## 1. 唯一的预留登记

- 目录：`/share/home/zixiao/descriptor_analysis/runs/shared_storage_reservations/`。
- **每条线只写自己的一个文件 `<线名>.json`**，用 `tools/shared_guard.py` 的 `claim()` 原子写入。线名用分支名去日期，例如 `p-recipe`、`s-recipe`、`d-recipe`、`data-d-descriptors`、`benchmark-b1`。
- 文件里登记的是**剩余的未来写入量**（已经写到盘上的部分 df 已经算过，不再登记），按以下三类分别写：
  - `node_disk`：某个节点的 `/` 或 `/tmp`；
  - `node_ram`：某个节点上进程的峰值常驻内存；
  - `shared_fs`：`/share` 或 `/lfshome`。
  - 路径只能写这四个挂载点之一。
- **每次轮询时重新 `claim()` 一次**：更新剩余量，并把有效期续到 24 小时之后。写完立即 `release()`。超过有效期没有续期的预留视为失效，不再计入。
- **不再**把别的线的数字抄进自己的配置或登记文件。现有配置里手抄的同行预留（例如 `budget_curve_plan.json` 的 `declared_peer_root_future_bytes`、D 登记文件里的 `registered_model_share_future_bytes`）从下一次新作业起停止读取，原文件保留为历史，不删除。
- STATUS 不再公告具体的存储数字。

## 2. 检查规则

- **用 `tools/shared_guard.py` 的 `check_with_timeout()`**：它在子进程里检查，60 秒没有返回就视为拒绝，所以 NFS 卡住时不会把调用方也一起卡住。
- 判定（数值和现行一致，只是同行预留改从登记目录读取）：
  - 节点本地盘：可用 ≥ max(10 GiB, 总量 10%) + 本次峰值 + 本节点其他线预留。`/tmp` 与 `/` 在同一块盘上时，两边的预留合并计算（模块自动判断）。
  - 共享盘：可用 ≥ 100 GB + 8 GiB + 本次峰值 + 其他线预留；如有新鲜的 UID 配额快照，也用同一标准检查配额余量。
  - 内存：MemAvailable ≥ max(16 GiB, 总量 10%) + 本次峰值常驻内存 + 本节点其他线预留。
  - 登记目录里有任何文件读不出来，就拒绝并给出文件名。
- **先登记，再检查**：启动前先 `claim()` 自己的预留，再 `check_with_timeout()`。两条线同时启动时会互相看到对方，偏保守但不会撞车。
- **只在两个时点检查**：作业启动时一次；之后单次写入超过 1 GiB 的阶段开始前一次。不在训练循环里逐个文件检查，通过之后不再复核。各线训练代码里已有的断点保存检查保持原样。
- 被拒绝：日报记一行原因，下一次轮询再试，不单独报告，不修改保留值。

## 3. 防止节点挂掉的两条硬规则

- **会写节点本地盘的作业，峰值必须登记。** 峰值取真实作业的实测值（第一次运行时测一次即可），没有实测值时按配置能算出的上界登记。
- **SSH 直接启动的进程不受 Slurm 内存限制，必须登记 `node_ram` 并通过内存检查才能启动。** 能用 sbatch 加 `--mem` 的，优先用 sbatch。

## 4. 迁移

- **在跑的作业不停、不重启、不改。** 新规则只用于新启动的作业和新的写入阶段。
- 各线在下一次轮询时：把 `tools/shared_guard.py` 放进本分支（本文件随附，内容一致），登记自己当前的剩余预留；新作业的准入入口改为调用它，并把原来跨工作树加载的守卫（如经 `MFM_model_v3` 工作树加载的 `v2_watch_disk.py`）换成本分支的这个模块。
- 迁移只跑 `tools/test_shared_guard.py` 一次。完整回归仍然只在开 PR 前做一次。
- 时间盒：迁移累计超过 4 小时或连续失败 2 次，记 UNRESOLVED，这条线继续用原来的守卫，日报记一行，主线继续。

## 5. 不做

- 不抄写、不核对、不公告其他线的存储数字。
- 不在训练循环里加新的检查，不对已通过的准入再复核，不为存储单独写报告或收据。
- 不为迁移停止、重启或迁移在跑的作业。
- 不修改 100 GB、8 GiB、10 GiB/10%、16 GiB/10% 这些保留值。
- 不删除旧的登记文件或配置。
