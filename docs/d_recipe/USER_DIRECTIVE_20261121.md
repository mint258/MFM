# D 线补充指示：开发面板 ExpansionRx 的 D3 几何（用户 2026-11-21）

适用：D 线任务书第 5 节（直接描述符对照）在开发面板上的 ExpansionRx 部分。回答 `DOWNSTREAM_INTERFACE.md` 中"缺 H 政策待用户答复"。其余条款不变。

## 1. 决定

ExpansionRx 的开发面板 D3 **沿用开发面板现有坐标，不补氢、不重新嵌入、不重新优化**，走与 QM9 相同的 `native_only` 路径。

理由：开发面板的 H0（A 组）就是在这些坐标上算的。B、C 组的 D3 用同一套坐标，A/B/C 三组的结构输入才一致。B6 v2 的补氢流程是给独立基线用的，不用于这里。

## 2. 执行

- 对原 5278 个 ExpansionRx 成员，用开发面板现有的坐标和每个成员的 source-frame 图计算六个分子 D3 字段（PMI1–3、PBF、体积、总 SASA）；逐原子 SASA 照旧单独保存，不进分子特征向量。
- 这些字段标记为"开发面板原坐标（无显式氢）D3"，在 manifest、`DOWNSTREAM_INTERFACE.md` 和最终报告中注明它和预训练 D3（含氢几何）的定义不同。
- 某个成员没有可用坐标时，该成员 D3 记为缺失，不填补，不从别的来源补几何。
- 与 QM9 component 按原成员、划分和顺序合并，形成完整的开发 D3（`complete_source_population=true`），然后照第 5 节执行 A/B/C 和组成参照。
- 二维描述符和组成参照照旧从 SMILES 图（隐式氢）计算，不受本决定影响。

## 3. 解读

- 报告写明：开发面板上 ExpansionRx 的 D3 基于无显式氢的坐标，数值不能和预训练 D3 或基准线 S′ UFF 上的 D3 直接对照。
- 最终结论以基准线上的 C1（S′ UFF 几何，含氢）为准；开发面板结果只用于开发阶段的描述。

## 4. 不做

- 不补氢，不生成新构象，不用 UFF 或 ETKDG 重新嵌入，不按 dev member 去猜基准线 record_id 借用 S′ 几何。
- 不改原成员、划分、D20/D3 定义或 D4 参数，不重拟合归一化。
- 不因本决定重跑已完成的 QM9 component 或任何训练。
