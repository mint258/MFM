# 源访问与执行边界

正式分析只使用冻结pilot面板的P数值，身份/角色与分组元数据从既有交付读取；没有重新扫描全1.19M的P标签。当前D6只尝试连接同MID/native_record_id的已冻结物理记录。大文件hash均引用已有值。

前期定位formal_record_index格式时，有一次调试读取了首元数据行组的全部列，再仅展示首行，其中带出了旧原生能量列。这次读取范围过宽，已作为执行偏差披露；这些值没有进入本研究面板选择、任何拟合或差值统计。后续正式生产者明确投影身份/图/角色列，没有把这些旧原生能量当作本版P标签。原调试脚本与日志保留外部目录，不隐去历史。

向量组件组装故障、NPZ重复解压及物理配对键更正均保留原日志；更正只消费既有缓存，错误实现的探索性结果不作为正式结论。旧数据、检查点、生产归一化与其他窗口训练没有改动。

阶段5复核D6依赖清单时，找到已登记的D6_full_physical_index_20261105_v3物理行定位库。此前UNRESOLVED是已检查owner/catalog未找到定位的阶段状态，不能扩写为源端不存在任何索引。已据该现成库的主键查询定位冻结物理记录，补充原始registry-cell图标量和固定2B候选元数据；没有创建新全源索引或搜索非面板标签。原始局部/向量值仍须独立验证源原子与参考系对应，不能由标量身份相同推断。

最终定点来源恢复43个图标量和35个坐标无关原子/pair标量；原子映射42961条全部唯一，由原source_to_M连接，pair保留有向端点与原组件口径。局部值SQLite仅缓存所选物理记录，不是新全源索引。原始有限值与共同pilot掩码只支持数值追踪，不独立验证原typed-mask物理策略。原参考系生产者两次失败的日志与成功缓存保留，31个原向量字段全量链UNRESOLVED；所有109字段的pilot及当前CPU准备仍已追踪。

2B严格复用匹配原输入/二进制的8个默认输出，只新增8次收紧SCF的PM7调用；额外TOTAL ENERGY比较直接解析同批已启用输出，没有新调用。xTB因无独立可用SCF-only十倍控制而未重算，没有用同时修改积分阈值的acc替代。原生能量定义、打印残差与数值差保留分开报告。
