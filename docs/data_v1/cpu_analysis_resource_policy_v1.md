# CPU 分析试点的资源边界

本轮任务是数据线CPU分析。用户最新要求CPU任务从实际CPU节点选择，站点当前cpu分区为compute-0-2、8–19；不把这项授权用于GPU。正式构象/QM仍限14–19，正式生成仍16CPU/64GiB并核全部用户声明内存85%，既有任务与源码不改。

用户此前允许小规模测试降低资源使用。`run_decisions_v4.json` 明确记录Root在本轮有限分析试点上的操作解释：其他CPU作业申报内存0时记作无明确上限，不记作实际0；只对登记的小试点采用实测内存、所有其他明确正数内存预留及本任务完整申请量之和不超过节点与OS较小内存的85%。这不是正式生成资源例外，也不能自动扩大试点人口。

仅policy文件列出的有限数据/元数据测试可用此入口，request必须pilot=true、analysis、16CPU、指定memory/规模/旧authority，且实际分配cpu分区。每次先核真实节点剩余CPU、全部用户队列、fresh quota及真实/proc内存；单次intent/receipt、Root锁、未知不重试与原提交器一致。

launcher每秒独立监控节点实测内存和自身进程树RSS，RSS达到申请量75%或节点包络超85%立即记录STOP；科学入口在下一stage/batch/派发之前检查STOP和<=5s心跳。已开始的工作自然结束，不发送终止信号。最终父作业只有子程序成功且全程无denial才返回0；监控全部证据与科学结果分开保留，不能只取子程序PASS掩盖资源失败。额外32MiB监控输出纳入quota预算。

代码新建为独立variant；科学函数以原源SHA、可逆编辑和AST证明核验，只增加guard/checkpoint，不改变配方、标签、掩码阈值、人口或数据值。8个新资源边界测试和科学variant的最少增量测试须在真实CPU allocation通过；旧已通过测试不重复。大数据不由登录节点读取或hash。
