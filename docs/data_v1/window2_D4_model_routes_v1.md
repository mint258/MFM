The source window2_normalization_v1 manifest contains exact numerical references, but not the model-target mapping. The historical final_release_v1 publisher requires obsolete receipt/ACK/two-replay inputs and another size-rho pass, so it is not called. This new publisher reads only existing small JSON statistics/models/field-map/schema/policy, without Parquet or label payloads, any fit, QA, replay, hashing or size-rho scan. It copies raw output references, values and masks unchanged.

Routes are indexed by (dataset,target_id), preserving actual source task/condition and original target IDs. Schema comes from the already delivered D3 v3.1 schema; the existing pure augment_schema adds only approved r73 sigma/pi training-view target metadata. Both datasets retain separate field maps, exact means/scales and energy reference models. A statistics row.field_id is the radix series ID; original fields are mapped by source_field_id/source_field_key and series key. Available raw/per-Z/vector/tensor series are catalogued, without treating component statistics as an anisotropic vector training route.

Scalar routes use original mean/std; eligible energy fields select <field_id>/residual and carry exact basis/intercept/coefficients plus explicit Z→coefficient mapping. Residual uses intercept+fsum(element counts*coefficients), then (residual-center)/scale. Empty/undefined/zero scale disables only that target normalizer; no epsilon/default denominator is introduced.

Existing formal D1 r674 normalization is read from /r674/normalization of configs/data_v1/interfaces/D1_v3_0_user_frozen_design_policy_20261029_v1.json: original type7 statistical-copy winsorized Frobenius std_ddof0, center0, one head scale. Existing exposure/loss-disabled/UNKNOWN flags are copied and never enabled by having a scale. Winsorized mean is named separately; it is not substituted for the uncomputed raw mean(F). Other vectors remain FIXED_ZERO_SINGLE_SCALE_POLICY_PENDING while the user decides norm std versus RMS. The publisher does not calculate RMS, choose a policy from recipe availability, or alter active statistics. Optional physical-route bindings contain only pointers into existing formally frozen policies; unsupported recipes remain pending.
