| 实际目标节点资源 | 执行方式 |
| --- | --- |
| 可分配CPU足够，GPU显存符合准入条件 | 普通sbatch直接运行 |
| CPU已分配、不足本任务，GPU空闲或占用≤30%且显存足够 | SSH立即运行，同时提交同节点sbatch接管作业 |
| GPU显存不足或未知，或节点DRAIN/DOWN | 不启动该卡上的新任务，等待其他合适资源 |

按实际GPU型号优先5090、4090、3090。Slurm当前没有GPU GRES，普通CPU分配不能阻止他人使用显卡；启动时再次核实UUID、显存与自有锁，其他用户进程保持不变。

当前额外要求至少18432MiB可用显存，覆盖既有B128有限容量测量的最大reserved约16556MiB并留余量；它是准入参考，不能保证全部TRAIN分子的峰值，真实OOM仍按96→64处理。接管增加的检查点和临时文件计入同一全局P磁盘预测57GB，非逐节点重复预留。

接管作业获得分配后，以唯一请求ID请求同一SSH训练保存并退出。训练在下一次完整优化器更新结束时保存模型、优化器、样本/更新计数、按样本计算的学习率位置、采样RNG、Torch CPU/CUDA RNG及统计窗口。先写 `.writing.<pid>`，关闭并同步后发布不可覆盖的最终 `.pt`，最后才写完成回执。预取使用独立规划游标，未训练数据不计入恢复位置。

接管器核实回执、原进程身份及退出状态，等待原CUDA上下文和自有UUID锁释放，再以新真实job ID恢复。保留原始运行、检查点和日志，台账记录来源/续训样本及退出原因；GPU成本扣除Slurm分配等待接管的重叠时间。SSH已完成全部训练和评价时，接管作业直接结束；异常退出或缺少完整回执时不冒充成功，也不读取不完整检查点。作业被取消后，后续恢复须检查既有回执和真实句柄，不能盲目重复提交。

磁盘预检、5秒运行期磁盘/配额保护继续生效。默认B128，真实OOM后96再64，科学配方、总样本预算及冻结11-07归一化不变。未来其他支持断点的任务采用同样调度决策，但必须接入其实际完整状态保存协议；不能对不支持断点的程序强行杀停。
