适用：配方线（分支 p-recipe）。本指示注册第 4 轮的具体臂，取代 `USER_DIRECTIVE_20261117.md` 第 7 条"第 4 轮只预留、不预先注册"；其余条款及 `USER_DIRECTIVE_20261117B.md` 不变。

第 4 轮测三件事：xTB 扰动梯度（类去噪物理信号）、PM7/xTB 多保真度、P 对 P′。基线一律用 **M2**（`configs/p_recipe/CURRENT_BEST.json` 现指向的 A1+B3+B4，seed 0，3M，R3 = 0.4680，R1 = 0.2975），不等第 3 轮的 M3。

## 一、xTB 扰动梯度（X1、X2）

### 现状

P 里有三个扰动字段：r624、r625 是原子级三维向量（xTB 梯度），r623 是分子级标量。训练时它们走单独一条路径：加载器把数据里存好的扰动构象 `pos_perturbed` 当输入再做一次前向，预测这个扰动构象上的 xTB 梯度（`v31_training.py`、`p_recipe_input.py`）。所以"输入偏离平衡的几何、预测物理力"每一步都在做。D1 留出拟合度：r624、r625 的 R² 为 0.99，r623 为 0.91。

局限有两点：

- 每个构象只有一个固定的扰动几何。S 的去噪每次重新采样噪声，P 的这一项永远是同一个扰动。
- 权重很小。按字段等权，两个梯度字段只占 P 总损失约 2%（2/109）。

### 臂

| 臂 | 相对 M2 的改动 | 回答什么 |
| --- | --- | --- |
| X1 去掉扰动梯度 | 关闭 r623、r624、r625，连同扰动构象的那次额外前向一起去掉 | 这组信号贡献了多少。顺带记录省掉一次前向后的样本/秒 |
| X2 加大梯度权重 | r624、r625 的损失权重乘 5，r623 不变 | 放大"类去噪"物理信号后会不会更好。只用这一个值，不扫参 |

X2 权重乘 5 后，这两个字段约占总损失的 8.5%（10/117），现在约 1.8%。

## 二、多保真度（F1、F2）

### 现状

P 里已有一批"同一物理量、PM7 和 xTB 各算一次"的字段，目前各自独立预测，相当于最朴素的多保真度联合训练。按家族粗对：

| 物理量 | PM7 | xTB |
| --- | --- | --- |
| 前线轨道／电离能、电子亲和能 | r49、r50、r61、r63 | r671、r672、r751、r752 |
| 偶极（气相） | r52 | r669 |
| 溶剂化（水／辛醇） | r398／r331 | r498／r459 |
| 原子电荷 | r68 | r668 |
| 键级 | r40 | r677（Wiberg） |
| 反应性（Fukui 类） | r44–r46 | r712 |

### 第一步：建配对表（F1、F2 共用）

上表只是粗对。精确配对按字段注册表的物理定义来建，输出 `configs/p_recipe/fixed_20261115/round4/fidelity_pairs.json`。配对规则：

- 同一物理量
- 同一分子状态（中性／离子态）
- 同一溶剂
- 同一粒度（原子／键／分子）
- 同一维度与符号约定

定义不能一一对上的（比如单位或符号约定不同而注册表无法换算，或一个字段对应多个字段），不进配对表，在表里单列"未配对"并写一行原因，不猜。配对表是 F1、F2 的唯一依据。

### 臂

| 臂 | 改动 | 回答什么 |
| --- | --- | --- |
| F1 共享物理头 + 方法嵌入 | 配对表里每对字段共用一个预测头，头的输入拼接一个可学习的 8 维方法向量（PM7／xTB 各一个）。目标值不变，两种方法仍按 11-07 参数各自标准化，逐字段损失权重不变 | 让表示编码与方法无关的物理量，方法差异由小嵌入承担 |
| F2 去重 | 去掉配对表里所有 xTB 字段，只留 PM7 | 跨方法冗余是在帮忙还是添乱。只改配置，不用开发 |

F1 的开发量约半天（共享头）。新逻辑只写一个单元测试：同一对的两个字段共享头参数，且方法向量不同时输出不同。验收用真实加载器加上一次逐头过拟合，不另做检查。

## 三、P 对 P′（PP，必要时加 M2C）

现在就做，理由：

- 不依赖第 3 轮结果，直接用 M2 配方。
- 前置条件已备好：P′ 版 A1 元素参考已在 CPU 上拟合完（`configs/p_recipe/label_parameters/UFF_A1.json`，作业 4535767）；P′ 来源可用清单为 TRAIN 1,192,951、Common VAL 7,560。
- 它直接决定要不要扩数据、用哪种数据扩。P′ 是 UFF 几何上的单点计算，比 P 便宜得多，越早有答案，数据线越早能规划。

做法：

1. M2 配方，`condition = Pprime`，`source = UFF`，A1 参考用 `UFF_A1.json`。11-07 归一化参数不变。
2. 字段取 P 与 P′ 的交集，按注册表字段 ID 对齐，交集清单写入 `round4/PP_fields.json`。这是本节唯一需要核对的一处：交集内每个字段在两边指向同一物理定义。
3. 交集等于全部 109 个字段时只跑 PP，与 M2 seed 0 比较。P′ 少了字段时加跑 M2C（M2 只用交集字段），PP 与 M2C 比较，否则不公平。
4. 噪声大小用 M2 seed 0 与 seed 1（`M2_SEED1_REFERENCE.json`）的 R3 差值。seed 1 还没到可复用状态时，先按下文规则判定，并注明噪声项待补。

### 对 9M T4 的影响

T4（9M 的 P′ 确认）改为可选。设 Δ = R3(PP) − R3(对照)，对照为 M2 或 M2C。三条同时满足就算"差距明显"：

- 配对 bootstrap（1000 次，分子为单位，seed 20261025）的 95% CI 不含 0
- |Δ| ≥ max(0.01, 0.05 × 两者 R3 较大值)，即 protocol 的最小改进幅度
- |Δ| 大于 M2 两个 seed 的 R3 差

差距明显时，在日报"待用户决定"里写"建议砍 T4，约省 38 GPU-h"；否则保留 T4，用 9M 确认。9M 本来就要等用户统一提交，所以这里不额外停。*更新：用户已预先授权按此规则自动决定，不再等待；9M-T3 取消，9M-T7 规则见 `USER_DIRECTIVE_20261118B.md` 第 2 节。*

## 四、判定（预注册）

- X1、X2、F1、F2 各自与 M2 seed 0 配对比较，沿用 `configs/p_recipe/protocol.json` 的胜负规则：R3 主分，R1 只报告；CI 下界 > 0，且 Δ ≥ max(0.01, 0.05 × 较大分)。
- 平局取更简单的配置。所以 X1、F2 平局时判为采纳"去掉"。X2、F1 平局时不采纳。
- 互斥的两组（X1 对 X2、F1 对 F2）都胜出时，按既有合并规则保留 Δ 较大者。
- 合并：M3 = M2 时，胜出项直接并入 M2 得到 M4，更新 CURRENT_BEST，并在日报记一行。M3 ≠ M2 时，在 M3 上加一条 3M 合并运行（M3 + 胜出项）对 M3 配对比较，胜了才更新 CURRENT_BEST。
- PP 不是配方组件，不参与合并，只按第三节规则给出 T4 建议，并作为数据线的输入。
- 单种子。第 4 轮属于筛选测试。*更新：有争议时最多补到 2 个种子，规则见 `USER_DIRECTIVE_20261118B.md` 第 3 节。*

## 不做清单

- 不做多次扰动（每次采样新的扰动几何）。要重跑 xTB，属于数据线。
- 不做以"扰动几何 − 平衡几何"为目标的坐标去噪。数据里两组坐标都有，可以免费构造，但那是 S 型目标，不在单独 P 的范围内。
- 不把 xTB 目标改写成"xTB − PM7"差值。思路和第 1 轮 A2（多状态改差值）一样，A2 是第 1 轮最差的臂（R3 Δ = −0.077，CI [−0.090, −0.063]）。
- 不扫 X2 的倍数，也不扫 F1 的方法向量维数。
- 不改 11-07 归一化，不改字段定义，不改 protocol 的胜负规则。
- 不提前启动 9M，不把其他线的结果并入配方，不改其他三条线的分支和文件。
- 不停止、不迁移在跑任务（C3 迁移按 11-17B 执行）。
