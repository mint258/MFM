## 0. 任务总纲

将现有 PhyChem-MFM 项目改造为一个用于**比较预训练监督信号及训练策略**的受控实验系统。

研究问题：在同一批分子、同一批构象、同一架构上，结构自监督（S）、描述符（D）、物理（P）三类预训练信号各自贡献多少下游能力，它们之间是互补还是冗余。

### 0.1 基本原则

- 优先复用已有实现，以最小必要改造保证实验可解释、目标可学习、共同表征可比较。
- **不以提高完整模型成绩为唯一目标。** 不预设 S、D、P 或任何组合必然获胜。
- P 未获胜、SDP 非最优，本身都不是工程故障，不得作为"实现有问题"的证据反复调参。
- 保留历史代码和旧结果，不覆盖原始数据或归档实现。

### 0.2 执行模式

- 审查与诊断阶段使用**并行子 agent** 加速（见步骤 1、步骤 5）。
- 各步骤完成后输出报告并**直接继续下一步**，不等待人工授权。
- 唯一硬性前置条件：正式矩阵开跑前必须先写出冻结协议文件（见 6.1）。
- 以下情况必须停下来明确提出，不得静默执行：改变监督含义、改变数据划分、改变正式实验范围、预计突破计算预算。

### 0.3 本阶段范围之外

以下内容属于第二阶段，不得自行纳入：

- P 的粒度拆分（只用能量 vs 只用电荷）
- 第二种架构（等变模型对照）
- 手性感知特征或任何新增几何不变量
- 模型规模扩展与规模律分析

## 1. 步骤 1：并行审计现有项目

启动四个子 agent 并行工作，各自输出独立报告，主 agent 汇总去重。

### 1.1 子 agent 分工

**子 agent A｜模型与架构**
主干网络结构、距离偏置注意力与半径掩码、任务分支与预测头、融合模块、几何对称性实现、保存与恢复逻辑。

**子 agent B｜数据管线**
LMDB 结构、clean / noisy 输入构造方式、构象与分子的对应关系、标签掩码、归一化统计量的来源与作用范围、现有训练验证划分方式。

**子 agent C｜任务与训练配置**
各任务的损失函数与权重、课程调度（含描述符 ramp 与第一阶段衰减系数）、优化器与学习率调度、实际训练步数与数据暴露量。

**子 agent D｜历史结果与元数据**
已有检查点的配置与元数据、已有重构报告、下游评估脚本、表征导出接口、毕设实验结果的可复现性。

### 1.2 汇总报告要求

- 按四类归档：**已完成并验证 / 已实现但未验证 / 需要修复 / 尚未实现**。
- 报告中声称完成的内容，与当前实际运行验证的内容分开记录。
- 必须明确标注以下已知差异：

> **毕设的下游输入是五分支拼接后的融合表征，维度随开启分支数变化；本实验统一导出共享主干输出 H0。因此毕设的下游数字不能作为 SDP 变体的结果引用，两套数字不得在任何分析或图表中混用。**

汇总完成后直接进入步骤 2。

## 2. 步骤 2：整理标签与数据

### 2.1 标签分类原则

按**信息来源**划分，而非按名称：

| 类别 | 定义 | 是否引入输入之外的信息 |
|---|---|---|
| S | 从被破坏的输入中恢复原输入 | 否（但见 2.2 的例外声明） |
| D | 2D 分子图的确定性函数 | 否，提供归纳偏置 |
| P | 需要额外量子化学计算 | 是 |

### 2.2 S｜结构自监督

包含：

- 扰动位置的元素恢复
- 几何去噪（目标为 PM7 优化构象）
- 成键与键级预测

**必须记录的已知混杂：**

> 几何去噪的目标来自 PM7 优化结构，因此该任务等价于学习 PM7 势能面附近的力场信息（Zaidi et al., ICLR 2023）。S 并非完全不含外部物理信息。此设计保留，因为它是三维去噪预训练的主流做法，且所有变体使用同一批构象，不破坏变体间公平性。但此事实必须在标签清单文件和最终论文中显式声明，并在解释"S 表现良好"时予以考虑。

**需要处理的任务设计问题：**

三维输入下，成键存在性几乎可由原子间距离直接读出，任务过于简单，可能导致该监督信号实际无效。处理方式二选一，并记录选择理由：

- 改为在扰动构象上预测成键
- 或只保留键级分类，去掉成键存在性二分类

### 2.3 D｜描述符标签

#### 2.3.1 排除规则

某个描述符满足以下**任一**条件即排除出 D，不纳入本阶段训练：

| 规则 | 说明 | 排除理由 |
|---|---|---|
| **R1 架构不可辨识** | 当前主干仅使用原子间平方距离，对镜面反射不变 | 模型原理上无法学习，强行训练只会产生无意义梯度并污染共享表征 |
| **R2 与其他监督重叠** | 该标签的信息已被 P 或 S 中的某个目标覆盖 | 会使 D 与 P 或 S 的对照失效，破坏因子实验的可分离性 |
| **R3 依赖构象** | 需要三维坐标才能计算，不是 2D 图的确定性函数 | 违反 D 的定义，使其不再是"仅提供归纳偏置"的一类 |

#### 2.3.2 已确定排除项

**按 R1 排除：** `chiral_tag`、`CIP_code`（R/S 标记）、以及任何其他立体化学标签。

**按 R2 排除：** `formal_charge`（与 P 的 MOPAC `NET ATOMIC CHARGES`在电荷信息上重叠）。

**按 R3 排除：** `RadiusOfGyration`、`NPR1`、`NPR2`、`Asphericity`、`Eccentricity`、`PBF`，以及其余全部三维形状描述符。

#### 2.3.3 需逐项审查的候选

下列标签存在与 S 重叠的嫌疑，Codex 须按 R2 逐项评估并给出保留或排除的结论及理由，不得默认保留：

- `total_degree`、`total_valence`、`total_num_Hs` —— 与 S 的成键 / 键级预测的重叠程度
- `EState_atom_type` —— 与 S 的元素恢复的重叠程度
- `hybridization` —— 可由几何与成键共同推出的程度
- `NumRotatableBonds`、`NumAmideBonds` 等键相关图级描述符 —— 与 S 的成键任务的重叠程度

判定标准：若某标签可由 S 或 P 中某个目标在不引入新信息的前提下几乎确定地推出，则排除。边界情况保留并记录理由。

#### 2.3.4 保留项（在 2.3.3 审查后确定最终清单）

图级：MolLogP、MolMR、TPSA、LabuteASA、ExactMolWt、NumValenceElectrons、HeavyAtomCount、NumHeteroatoms、NumHAcceptors、NumHDonors、FractionCSP3、RingCount、NumAromaticRings、NumAliphaticRings、NumSaturatedRings、NumHeterocycles、NumBridgeheadAtoms、NumSpiroAtoms、BertzCT、HallKierAlpha、Kappa1/2/3

原子级：is_aromatic、is_in_ring、min_ring_size、donor / acceptor 标记、EState_index

#### 2.3.5 实现要求

被排除的描述符，其预测头一并移除，不保留空跑分支。D 关闭时，所有描述符相关参数不得参与计算或更新。

### 2.4 P｜物理标签

- PM7 生成能（图级）
- MOPAC `NET ATOMIC CHARGES`（原子级）

### 2.5 数据核查要点

- 各组合使用**同一基础分子和构象集合**；缺失标签采用统一、可追踪的处理规则。
- 训练验证**按分子身份分组**划分，不得按 LMDB 记录编号划分。同一分子的全部构象必须落在同一侧。
- 归一化统计量**只用训练数据**计算。
- 正式训练前完成去污染：按 InChIKey 移除与所有计划下游测试集重叠的分子，生成可追踪的清单文件并记录哈希。
- 核查原子顺序、电荷与几何的逐原子对应关系。
- 核查目标泄漏：输入中是否已直接包含某个预测目标。
- 核查 clean / noisy 输入与各标签的一致性。
- 核查预训练与下游的构象生成流程差异，并记录。

优先修复数据管线和任务定义，**不自动新增大规模量子计算**。

### 2.6 输出

生成标签清单文件，逐项记录：来源、预测层级、单位或类别、输入视图、目标对应的分子或构象、有效标签掩码、归一化方式、排除项及其适用规则。完成后直接继续。

## 3. 步骤 3：必要的架构调整

### 3.1 硬性约束

- 所有启用任务应能更新共享编码器输出。
- **任务开关不得改变下游表征的定义、维度或导出位置。** 统一导出共享主干输出 H0。
- 下游推理不得依赖真实预训练标签。
- 保留原子级导出与统一图级接口。
- 允许不同任务使用不同预测头或适配容量，但**同一任务在不同标签组合中的实现必须完全一致**。

### 3.2 适配模块选择

Light / Expert / 固定逐任务适配的选择，由目标可学习性、共同表征的开发集表现和计算成本共同决定。

> **不得仅因 Expert 的预训练损失更低，就认定它提供了更好的表征。** 预训练损失与下游迁移能力之间不存在必然的单调关系。

### 3.3 验证项

- 几何对称性：刚体平移与旋转下表征不变
- 掩码与 padding 的正确性
- 任务关闭后无意外梯度与参数更新
- 保存与恢复的一致性

### 3.4 异常处理

若发现某目标在当前输入下不可辨识，先调整任务或输入定义并记录理由，**不得判定为该类监督无价值**。

不进行开放式架构搜索。

## 4. 步骤 4：拆开标签组合、训练策略与优化规则

### 4.1 标签矩阵

`none / S / D / P / SD / SP / DP / SDP`，共 8 个条件。`none` 为配对随机初始化，不需实际预训练。

### 4.2 训练策略

- **直接联合训练**为主基准。
- 分阶段引入仅在少数固定组合上作为策略对照。
- 不运行"所有组合 × 所有策略 × 所有适配模块"的完整乘积。

### 4.3 必须修复的已知问题

现行课程中，描述符损失在第一阶段步数阈值之前权重为零，导致 D-only 条件在该区间内无有效更新。

**修复要求：所有条件从第 0 步起，即对其所有已启用的任务施加有效监督。**

### 4.4 权重与归一化

明确组内与组间的损失归一化和权重语义，避免某类监督的强度被其任务个数直接决定。

> 主要风险点：D 的任务数远多于 P。若按任务求和，D 会在总损失中天然占据更大比重，使"D 更有效"的结论变成权重假象。

Uncertainty Weighting 可作为敏感性分析方案，但不替代对公平性的显式说明。

### 4.5 策略比较需记录的量

实际更新次数、分子与构象及输入视图的暴露量、每任务有效标签量、权重随训练的变化曲线。

区分两类不同问题：固定总预算下比较训练配方 / 隔离训练顺序本身的影响。

## 5. 步骤 5：分级试跑

可并行化的诊断用子 agent 分发（例如不同条件的正确性检查、不同目标的学习情况评估并行执行）。已有有效证据的部分可跳过重复工作。

### 5.1 基本正确性

每个计划条件能完成前向、反向、保存恢复、表征导出；启用任务产生有效梯度，关闭任务无意外更新。

### 5.2 目标学习情况

在**按分子独立划分**的真实验证数据上，报告**逆归一化后**的指标，并与下列基线对照：

| 目标 | 对照基线 |
|---|---|
| PM7 生成能 | 基于元素计数的线性回归 |
| MOPAC `NET ATOMIC CHARGES` | 按元素类型的均值预测 |
| 几何去噪 | 直接输出带噪输入坐标 |
| 元素恢复 | 多数类预测 |
| 键级 | 多数类预测 |
| 连续描述符 | 训练集均值 |
| 二分类描述符 | 多数类预测 |

**判定方式：** 不设固定数值阈值。Codex 须结合每个目标本身的难度、标签噪声水平、该目标在化学上的可预测性上限，判断模型是否已学到实质信息，并在报告中给出完整数值与判断依据。

例如：MOPAC `NET ATOMIC CHARGES`受元素类型强烈约束，按元素均值基线本身就相当强，因此小幅超越基线不足以说明问题；而几何去噪基线很弱，需要明显优于它才算有效。判断必须说明理由，不接受仅罗列数字。

未达标的目标，按步骤 3 的流程排查实现与输入定义，**不得直接判定该监督无效**。

小数据记忆试验仅用于排查实现错误，**不作为泛化证据**。

### 5.3 最低限度迁移检查

- 使用固定的小型开发任务集，统一的冻结编码器加轻量读出流程，保留原子级后聚合。线性探针作为互补。
- **开发任务集只能使用最终评估集的训练部分做交叉验证，或使用完全不进入最终评估的独立数据集。** 任何情况下不得接触最终测试数据。
- 不为每个变体分别挑选最有利的读出方式。

### 5.4 训练成熟度判断

考察逐任务学习曲线、学习率调度的实际阶段、有效数据暴露量、开发集表现。

**判定方式：** 不设固定数值阈值。Codex 须结合优化理论和实际训练动态进行分析，至少涵盖：

- 学习率是否已退出 warmup 并进入衰减阶段；在 warmup 期内的平台不构成收敛证据
- 各任务验证指标的变化趋势是仍在单调下降、已进入噪声波动，还是出现过拟合反转
- 不同任务的成熟进度是否一致；若某任务明显滞后，需判断是任务本身更难还是权重分配不当
- 有效数据暴露量是否足以支撑当前模型容量
- 动态加权下的总损失变平**不构成**收敛证据，因为权重本身在变化

结论须明确说明是"训练充分"、"训练不足需延长"还是"已出现过拟合"，并给出依据。不得仅凭总损失曲线形状下结论。

### 5.5 排查顺序

发现问题时按以下顺序排查，**避免一次改变多个科学变量**：

数据对应 → 输入视图 → 归一化与掩码 → 梯度路径与任务头 → 优化器与训练预算

## 6. 步骤 6：冻结协议并立即执行

### 6.1 冻结协议文件（正式矩阵的前置条件）

生成带时间戳的协议文件，**内容齐备后方可开跑**。必须包含：

- 正式实验清单，逐项写明该实验回答什么问题
- 共同数据集与去污染清单的版本标识或哈希
- 编码器配置、任务定义、训练策略、随机种子、训练预算、检查点保存规则
- **最终下游数据集清单**
- **下游读出方式**
- **统计检验方法与主要比较对象**

后三项必须在此刻写定，不得等预训练结束后再决定。

### 6.2 配对与重复

- 共享参数初始化与数据顺序尽量配对。
- 关键比较优先安排独立预训练重复。
- **多个下游读出种子不能替代多个预训练种子。**
- 正式矩阵从配对的随机初始化开始，**不得让任何条件继承旧预训练权重**。

### 6.3 预算

- 用步骤 5 的实测数据估计计算、数据加载与存储成本，覆盖代表性轻条件与最昂贵的计划条件。
- 若无法同时匹配数据暴露量和计算成本，**明确声明主控制口径**，不宣称所有变量均已对齐。
- 总预算上限与存储上限按实测结果确定并写入协议。预计突破时提出，不静默执行。

### 6.4 执行纪律

协议冻结后按范围运行、保存、恢复，无需等待进一步授权。

- **不得**按各条件各自的最低加权验证损失分别挑选"最佳模型"。
- **不得**不断延长某个条件直到出现期望结果。
- 影响科学比较的修改必须形成新版本协议文件，并说明哪些实验需要重跑。

## 7. 步骤 7：交付内容

1. **现状审计与决策记录**
   四个子 agent 的原始报告与汇总；复用、修复、验证及未解决问题清单。

2. **标签、数据与实验定义**
   最终目标清单（含 D 的排除项及适用规则、S 的 PM7 混杂声明）、划分与去污染记录、主矩阵及策略对照。

3. **可运行实现与验证证据**
   配置文件、关键测试、真实数据训练日志、保存恢复与表征导出方式。

4. **试跑分析与预算建议**
   原单位下的目标精度与基线对照、最低限度迁移结果、训练成熟度分析、资源实测数据。

5. **正式训练状态**
   冻结协议文件路径与时间戳、各条件执行进度、是否存在阻塞项。

文件结构、具体实现、开发集超参数和小规模诊断可自主决定，无需逐项确认。
