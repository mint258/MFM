# 训练系统指标与 1000 更新平均损失

`v2_training_diagnostics.sbatch` 是独立 CPU 记录作业。读取实际训练 CSV 与实际节点元数据，不加载模型或数据样本，不修改训练、检查点、优化器或随机数状态。

每次真实 Slurm 执行对应原损失 run `m3-<job>` 和诊断 run `m3-<job>-diagnostics`，共享 project/group，并显式记录训练 job、node、GPU UUID、原训练来源。W&B 内部诊断步序独立于科学样本计数；损失窗口用 `samples/cumulative` 作横轴，系统指标用实际观测 Unix 时间作横轴。

约每 30 秒采样实际卡的功率、GPU/显存利用率、整卡显存、本作业 GPU 进程显存、温度、SM/显存时钟及其他进程数量。按 UID1278 与 Slurm cgroup 同时确认本作业主进程，再记录其 RSS、区间 CPU、读写字节率和主缺页率；补充节点可用内存、load1、根盘/输出盘可用字节与 inode，以及同一区间实际样本吞吐。主进程指标不冒充包含所有 CPU 子进程的总用量。功率属于整张物理卡；相邻成功观测之间的梯形能耗估计带有效区间秒数，缺测或超过 90 秒的间隔不积分。未提供的传感器留空，采集失败明确记录，训练继续。

每个执行从其第一条实际 CSV 更新开始，连续、互不重叠地汇总 1000 个优化器更新；分别记录 total/S/D/P/其他已有分项的算术平均值、各分项有效条数、首尾更新与样本数。历史补录条数明确标记。缺失分项不作零值；非连续更新不能悄悄拼成完整窗口；终态余数另存并标为 partial，不当成 1000 步均值。不同续跑执行保持独立，重放工作不计作新的科学样本。

持久记录位于 `WANDB_20261110/diagnostics/<job>/`：真实 SDK、`system_metrics.jsonl`、`loss_windows.jsonl`、`latest.json` 和运行状态。新 GitHub 10 万样本点附上最近诊断观测及其独立时间/样本计数，明确它与边界的对齐方式；原发布历史保留。系统指标从接入时开始采集，历史平均损失使用原 CSV 补录。
