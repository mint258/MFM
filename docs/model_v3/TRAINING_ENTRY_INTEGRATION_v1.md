# Real training entry integration (source-only)

This change connects the existing proxy, recipe S/P/SDP, full-TRAIN and explicitly registered grid paths to the single training-execution adapter. It does not freeze a model or recipe, grant final-data authority, launch training, or certify GPU capacity. No tests have been executed by the author. Root must integrate the adapter and H0 consumer, run the owned CPU checks and full regression, and close actual Slurm/source/resource results.

## One construction and recovery path

`run_proxy_experiment.py run` validates the immutable request and original final-data gates, binds the pinned `PreparedV3Batch` provider, then calls `build_experiment`. An explicit top-level `configuration.training_execution` selects SA1's `build_training_encoder`. Complete PD heads are constructed before `make_training_optimizer`; `finalize_training_execution` supplies the one model/optimizer contract. The original AdamW path and absence of new serialized keys are retained when the option is absent. Unknown nested execution keys cannot silently enter the plain factory.

The same builder handles S, P, SDP and fixed two/three-view policies. The effective physical view count remains one for a P-only run. Selective BF16 must be explicitly declared in both the training policy and proxy precision; geometry/heads/loss remain outside the selective encoder autocast. C1-a/b support, packing, optimizer dispatch, allowed precision and auto-policy qualifications are owned by the shared adapter, rather than a second implementation here.

The workload projection binds numerical model/heads/groups/fields/views/training-view/schedule/sample-budget/batch/loss/clip/optimizer and both validation populations. Actual registry/normalization content and the original input projection are retained. Scientific data-release identity comes from the bound D1/D2/D4/D5-or-D6 evidence; opaque provider receipt and exact request/configuration hashes remain in the original CP/RUN_BINDING provenance. Resource/admission revisions cannot silently change the numerical workload. The consumer calls `validate_training_workload_request` to reconstruct this projection from the actual invoked request/configuration, without reopening targets.

A new *optional and explicitly registered* `recipe_identity_schema: model_v3_training_recipe_identity_v2` removes only GPU UUID/name routing and pretraining seed from the seed-common recipe identity. Old configurations still use the original seed-only exclusion. Actual device, threads, determinism, source/data/model and numerical policy stay bound; actual UUID/name remain in the immutable configuration, Root admission, trainer bindings and exact capacity qualification. This is not permission to reuse a profile across seeds, GPU models, UUIDs, workloads or residency.

## Forward observations and safe checkpoints

Every actual forward, including the 500-update group probe, enters the adapter's role context. Main TRAIN metadata is captured immediately after its forward, before a probe can replace last-forward observations. Only completed effective updates advance the original sample/update clock and receive TRAIN observation rows. Every validation batch is captured under its own role; begin/complete calls bind the declared whole fixed population. Probes do not create extra draw or optimizer cursors.

The CLI attaches the original owned-process/output/GPU samplers as a resource callback. Unknown GPU process memory is rejected. Rows stream to bounded `training_capacity.jsonl`; they are not retained as an unbounded Python trace. Final `training_capacity_configuration.json` uses the first actual forward's environment and exact request ref; `training_capacity_summary.json` remains pending independent outer C0. `CHILD_RECEIPT.training_execution_capacity_artifacts` contains exact `configuration`, `summary`, `steps` rawrefs. CPU engineering observations explicitly carry no CUDA qualification. Root must close the actual supervisor, sacct and native SDK before a profile can qualify automatic selection.

The original checkpoint envelope, sample-clock controller, regular recovery checkpoints, atomic save, source checks and outbox remain. Only opt-in adds the same contract at `trainer.contract.training_execution` and `extra_state.execution.training_execution`. Resume compares both to the reconstructed live model before changing flags, tensors, AdamW or RNG. The source-bound adapter owns the FP32/no-internal-AMP export mapping; READY calls SA4's pure metadata capability helper and still requires the original six layers/512 dimensions for a primary panel.

Only opt-in outbox events add the contract and H0-map canonical hashes. The unchanged ACK schema compares both event hashes to the pair's full provenance, invokes the bridge's one compact cache projection, verifies every candidate/random cache execution-source hash and original COMPLETE, and retains the existing exact panel/SDK/outer-C0/replay rules. A new cache is a new identity; no old cache is claimed unchanged after source changes. An old event cannot ACK an unbound new-execution cache. Synthetic comparator tests supply no real panel or SDK authority.

## WSD and final grid scopes

The WSD path first reconstructs and strictly loads the complete original parent contract. Its thin opt-in hook calls `rebind_training_execution` over the *same* model and optimizer. Only the original WSD-allowed schedule/sample-budget changes are projected into the child workload. The child gets its own observer and contract. Automatic selection requires a separately closed exact child-workload profile with identical resolved execution flags. Parent capacity is not renamed. Original parent refs, sampler cursor, AdamW, RNG, LR continuity, clock, saved points, family/canonical ledgers and guards remain. The WSD CLI reuses the same observation setup/finalizer and records actual child committed cursors; no new monitor is introduced.

The new `authoritative_grid_train` request mode has `scope=grid_cell` and an explicit model-side `model_v3_grid_TRAIN_consumption_v1` projection. It is a selected subset of frozen TRAIN, with exact base/subset membership, geometry, existing conformation selection, budget and release evidence. The guide's handoff smoke specifically requires 120000 TRAIN molecules, k=2 and 1000000 base draws. A source population role named FULL is not a full/grid training release.

`prepare_recipe_experiment.py grid` prepares a proposal with no registrations or Root admission. Its input manifest contains the existing registered rule-policy ref, base request, pinned authority adapter, exact input projection, grid contract and explicit sample/validation/checkpoint/schedule plan. `admit` invokes the shared final request/provider validation. Actual execution requires clean committed source/tree, public/local policy mapping, budget/validation/grid and execution registrations, actual frozen model/recipe rawrefs, D1/D2/D3/D4/D6 and the original SDP evidence. The pinned authority must implement `verify_and_bind_model_v3_grid_TRAIN_inputs`, return the exact final `ProxyInputs`, and independently verify the subset against base TRAIN. This does not invent a data-line release schema or make a draft adapter authoritative.

The existing scientific proxy remains exactly 240000 TRAIN molecules with D5; full convergence remains the existing entire-frozen-TRAIN D6 path and its independent finite resource/storage/profile/quota gates. Long-run/family accounting, original per-segment 2GiB/wall/RSS limits, milestone and regular-recovery policy are not enlarged or replaced here. Unknown or missing final releases, capacity profiles, policy or storage declarations fail closed. There are no actual final D5/D6 evaluations, B-star or frozen recipe results in this source change.
