# 提速线补充指示（用户 2026-11-17）

适用：提速线（分支 perf/sync-free-20261117，PR #13）。本指示覆盖任务书中与之冲突的条款，其余规则不变。

## 背景

PR #13 交付了全部开关的代码和 CPU 验证，但 GPU 测速和 A/B 数值验收一项都没有执行。原因是任务书写了"某种卡型没有空闲卡就跳过、不等待"。用户的决定是：**提速测试必须在配方线提交 9M 确认运行之前做完。** 配方线会暂缓 9M，并把下一张空闲卡优先给本线。

## 修订后的规则

1. **GPU 测速和数值验收是必做项。** 至少在一种卡型上完整完成，按先空闲者取：5090 > 4090 > 3090。没有空闲卡时排队等待，每 30 分钟查看一次，**不再跳过**。其他卡型只在有空闲卡时补测，属于可选。

2. **一次拿卡、连续做完。** 拿到卡后，在同一次 GPU 分配里依次完成全部内容，避免反复等卡：
   1. S0：GPU 时间线、同步定位、噪声底；
   2. S1–S5：各自的 A 类或 B 类验收，加 1000 步测速；
   3. S6：仅当 S1 之后每步同步数为 0 时做；
   4. S7：核数扫描，限这张卡所在节点实际空闲的核；
   5. S8：累计组合。

   预计 3–4 GPU-h，上限 6 GPU-h。超出只报告，继续做完。

3. **基准配置**沿用任务书中的 `round3/M2.json`，它就是当前最优配方。配方线发布 `configs/p_recipe/CURRENT_BEST.json` 后，若它在本线完成之前更新为 M3，本线仍以 M2 为基准，不重测。

4. **"有效"的判定**：
   - 只测了一种卡型时，提速 ≥ 5% 且通过对应验收即为有效，并注明只测了一种卡型；
   - 测了两种及以上卡型时，按原标准：至少 2 种卡型提速 ≥ 3%。

5. **交付物与截止。** 交付一页结果：建议开启的开关组合、累计提速倍数、各项验收结果。完成后立即推送，并更新 PR #13 的描述。交付后由用户决定 9M 运行启用哪些开关；配方线在 9M 启动时读取这个决定。

## 不做清单

- 不做超过 1000 次更新的训练，不做下游评价。
- 不因 CI 中既有的 202 项历史错误去修改检查器或删除历史资产。
- 不修改其他三条线的分支和文件。不停止、不抢占任何在跑任务。
