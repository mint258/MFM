## Checks and read-only inputs

`verify_native_history.py` retains the tested B3v2 streaming SDK decoder and
scientific scalar/step comparison. It compares every allowed native history row
against every original journal row, exact explicit step and payload; validates
SDK run ID **and declared run name**, source config/request/seed bindings,
final summary score/status, native exit0 and clean EOF. Native ancillary metric,
summary, config and other records consume the native quota but not history quota.
Actual record counts are reported only after complete successful scanning.

Limits remain500,000 total native records,100,000 history rows,128 MiB SDK,
32 MiB journal,4 MiB single record,32 KiB journal line,64 MiB output and180s.
Original SDK/journal bytes are hashed before and after; no whole-history list
is accumulated. All scientific rows are compared and their canonical stream
hashed, but **no per-update history file is exported** in this primary tool.
Only compact series counts/ranges/first/last and provenance are emitted.
No SDK original is copied, modified, uploaded, synced, pruned or deleted.

`primary512_scope.py` checks the actual raw-byte chain from successful486 A00
READY/export admission through the launched v2 spec, request, result and guard.
It loads the exact SHA-bound, frozen v2 `export_admission.py` implementation
declared by the launch spec (stdlib only) and reuses its original checks for
full native20/500 acceptance, successful export supervisor/run cleanup, standard
`model_state`, original complete configuration/recipe, source inventory, seed,
RNG proof and bundle bytes. It rehashes the actual exported checkpoint as opaque
bytes, capped separately at512 MiB; it does not deserialize or run it. This
separate weight bound does not change the128 MiB native SDK bound. Recipe JSON
must physically declare512x6. A00 fp32/non-fused control options, export486 and
the exact full configuration cannot be replaced by A06, a384 model, another
path/hash/state key or a reconstructed dimension-only configuration.

Request/result references legitimately omit `bytes`; READY/spec references
retain independently measured sizes. Cross-format comparisons use the same
path/SHA/state semantics and explicit optional-size checks. The frozen source
admission helper still checks the physical READY size/hash authority, so the
522 reference-shape fix never weakens byte integrity.

Current evaluation admission must bind actual successful Slurm C0/ElapsedRaw,
the exact launched spec and a successful evaluation supervisor with no remaining
descendants or private-storage failure. Guard/result/request/spec source hashes
and unchanged precision policy must agree. Export receipt age is not redefined
after the fact: it was required fresh at CPU preparation/GPU launch; successful
immutable historical export closure is rechecked now. The current evaluation/
quota receipt must be fresh. No SSH, sacct, quota or scheduling command is run
by these tools; Root supplies their actual observations.

`make_primary512_report.py` checks matching random512 state/configuration,
membership, geometry, target-free H0 inventories, packing and runtime; the full
nine tasks and18 cells; both separate9-cell readouts;1000 paired molecular
bootstrap draws and existing intervals. It verifies all normalized improvement
formulas and equal-weight means, without recomputing targets or predictions.
Every cell and negative result stays visible. Small SoM molecular populations
and CI/generalization limits are explicit. Single-seed SD stays unavailable.

Outputs are compact certificate/source refs and per-series scalar statistics,
18-cell aggregate JSON, Markdown and one typed run-summary CSV row. CSV obeys
the unchanged repository checker columns; per-task data stays aggregate JSON/
Markdown. Configuration SHA in CSV means the full run request's raw SHA. No
member IDs, predictions, H0 tensors, target frames or full scalar history enter
these outputs or Git. The original core independent-verification flag remains
false; a separate successful certificate is the new evidence, never an edit to
the original result.

One-GPU-hour claims use **both** actual guard inclusive wall through SDK finish/
cleanup and actual outer Slurm allocation seconds. Core elapsed alone or the
guard flag alone is insufficient. Over-budget observations are reported as such,
not disguised by excluding overhead. This is one admitted physical UUID's
observed allocation; scheduler GRES isolation is not claimed. Torch allocated
memory is the process allocator high-water since its last reset, not device-
global, driver/process-tree or guaranteed H0-only peak. No85% capacity claim is
inferred from that counter.
