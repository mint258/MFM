# Generic Native long archive Root closure and reviewed entry append

Source only. This package does not submit or run a Slurm job, decode/hash an
SDK or scientific journal, invoke API/SSH/model code, or edit the original
archiver. Root is the actual executor. Its supported producer is the exact
frozen native_closed_long_archive_v1 source inventory2ad22f85..., not a
fixed jobID or fixed two-run list. Membership remains the request/result1..3.

## Calls

After Root's stdlib AST and exact source/dependency hash review, use the same
login Python as the existing metadata tools. Global source flag comes first.

    PY -B SRC/close_and_append.py --source-pins-sha256 PIN close \
      --request ACTUAL_REQUEST --request-sha256 ACTUAL_REQUEST_SHA \
      --submission ACTUAL_SUBMISSION --submission-sha256 ACTUAL_SUBMISSION_SHA \
      --output N/FRESH_ROOT_EVIDENCE_DIRECTORY

All values are actual, machine-bound inputs. There is no prefilled future
success. Root output must be a fresh immediate directory under the project
runs/model_v3_20261026. The source derives archive output, prepared receipt,
result, index, proposal and supervisor from the actual submission bindings.
Fresh sacct must prove the exact owned16CPU CPU-node archive job COMPLETED0:0.
The same-job supervisor/kernel/command/source/private/remaining closure,
original four zero-skip export tests, request/prepare/source/manifests, strict
audit/BATCH/actual-C0 proof and prior index references must all match.

The closer writes FRESH_ROOT_EVIDENCE_DIRECTORY/CLOSURE.json with status
ACTUAL_ARCHIVE_C0_METADATA_CLOSED_VISUAL_REVIEW_PENDING. This proves the local
archive execution metadata, not independent current SDK content. The original
C0 worker's before/after copy/hash/normalization evidence is reused. Root only
stats source/copied SDK/log/journal/normalized files and checks sizes; it does
not open those payloads or CSV. Metadata certificates/index/source/proposal are
rehashed. Old indexes are read-only and preserved exactly. The source binds the
historic allocation-time quota receipt without treating it as a fresh quota
after the job has finished. It reserves or trains nothing.

Root then actually renders and inspects every1..3 page. Supply a bounded JSON
visual receipt with this exact shape:

    {
      "schema": "native_S_closed_long_archive_Root_visual_review_v1",
      "status": "ALL_EXPLICIT_DEFAULT_CURVE_PAGES_RENDERED_AND_INSPECTED",
      "archive_job_id": "ACTUAL",
      "archive_result": {"path": "ACTUAL", "bytes": 0, "sha256": "ACTUAL"},
      "request": {"path": "ACTUAL", "bytes": 0, "sha256": "ACTUAL"},
      "no_scientific_adoption": true,
      "review_scope": "Actual default numeric curve/identity/status/point/link review; describe exclusions honestly",
      "entries": [
        {
          "run_id": "ACTUAL",
          "page_path": "ACTUAL",
          "page_bytes": 0,
          "page_sha256": "ACTUAL",
          "screenshot_path": "ACTUAL",
          "screenshot_bytes": 0,
          "screenshot_sha256": "ACTUAL",
          "rendered_and_visually_inspected": true
        }
      ]
    }

These placeholders are explanatory and invalid as evidence. Run set must
equal the actual closed result exactly. Distinguish scientific history rows
from selected training-series points; default curve review does not claim
exhaustive dropdown/all-metric UI testing. Linux paths or explicitly verified
same-project X:/Y: Windows mount aliases are accepted. Screenshots must be
physical ordinary PNG files under project runs/model_v3_20261026.

    PY -B SRC/close_and_append.py --source-pins-sha256 PIN append \
      --closure FRESH_ROOT_EVIDENCE_DIRECTORY/CLOSURE.json \
      --closure-sha256 ACTUAL_CLOSURE_SHA \
      --visual-review ACTUAL_VISUAL_REVIEW --visual-review-sha256 ACTUAL_REVIEW_SHA

Append revalidates the closure/source/input/proof graph and fresh actual parent
C0, then compares current full page/screenshot bytes+SHA with Root's receipt.
It locks the existing unified entry with O_NOFOLLOW/flock, writes the entire
prior bytes to FRESH_ROOT_EVIDENCE_DIRECTORY/UNIFIED_ENTRY_BEFORE.html,
and uses one O_APPEND write containing only the original worker proposal.
The old prefix and inode remain; the marker must have been absent and occur
exactly once afterward. Every preserved old index is checked before and after.
It writes APPEND_ACTUAL.json referencing both closure and actual visual proof,
including the honest visual scope. It does not rewrite CLOSURE.json or pretend
the former pending visual state had already been verified.

No retry, delete, duplicate append, entry replacement or repair is automatic.
Existing backup/application or a changed original entry causes refusal; Root
reviews an interrupted operation. Original source artifacts/indexes and
offline/online flags are never edited. Actual online sync evidence remains
separate from local files and from scientific/model/B acceptance. Page review
does not establish science. The archiver's16CPU16GiB/900s/RSS12GiB/whole-private
2GiB/archive256MiB/forest104GiB limits remain untouched. Root metadata JSON is
bounded1MiB per file; old entry is bounded1MiB and backed up once. No additional
QA parent, dispatcher, RPC, daemon, API call, training or recipe change exists.
