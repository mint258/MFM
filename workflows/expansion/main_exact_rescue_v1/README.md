# Main exact FP rescue and terminal Alpha import

This is an independent CPU implementation adapter, not a full-pool release or an
Alpha execution claim. It leaves Alpha201 and live232/233 files/code unchanged.
Root alone builds/deploys/submits. Source preparation does not constitute native
validation, actual transport, a finished job, or a speed measurement.

Main scores each DISTINCT exported fingerprint from canonical-hex-text MD5
prefixes8,9,a,e,f against all1,196,122 original196 reference entries in original
order. It uses the unchanged inverted Core5 integer implementation, Python's
single final numerator/denominator division, and the original nine score columns.
No FP/chemistry recomputation, approximate index, reference subset, or score retry
is introduced. Alpha's two original logical work partitions remain authoritative;
rescue adds closed FP-cache rows only. Concurrent Alpha duplication is possible
and is checked exactly before import; no guarantee of zero repeated computation.

## Exact transport

`EXACT_RESCUE_TRANSPORT_V1` is a small metadata descriptor with source_endpoint,
source_uid, destination_endpoint, destination_uid and
`files:[{origin:{path,bytes,sha256},replica:{path,bytes,sha256}}]`.
The original source JSON body/paths/UIDs remain byte-identical. Only explicit
replica mapping changes location. Source/destination SHA and bytes must be equal;
actual destination ownership, same-FD/frame/SHA and final frames are verified.
Do not rewrite original Main provenance into Alpha UID/path claims.

Alpha importer uses a separate Main-to-Alpha descriptor covering Main manifest,
score catalog/parts, actual Main raw sacct, preflight, and new build manifest.
The binary may be archived separately but is never executed on Alpha.
