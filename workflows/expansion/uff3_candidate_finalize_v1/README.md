## Full integrity closure

The producer verifies frozen source JSONL SHA/EOF, source row SHA,2.5M unique
MID/CID/full-key/stream-rank and both1.25M rank ranges. Closed generation index
and batch membership must match; all shards must be present and disjoint. No
outside-shard pilot rows can be silently discarded/regenerated. Current normal
pilot-to-full uses one actual same stage; implicit cache redistribution is not
implemented here.

Every saved cache/packet/event-chain whole SHA is checked with own native
regular-file UID, stable FD/path frame, and source/recipe/seed/once identity.
Cache/packet validation only hashes stored numbers; no alignment, optimization
or descriptor calculation is replayed. Recorded intent IDs reject duplicate
native attempts. Original producer/verification-worker evidence remains in the
per-MID evidence catalog; absent original per-MID native PID is not invented.

Actual saved F64 bit fingerprints are compared against all delivered D20/D3
family values, explicit-H atomSASA arrays, coordinates, energy and native IDs.
Source CID/key/version/stream/rank/once/packet SHA and original D20 names/masks
must agree for each family row. No float32 family is accepted. Three saved
conformer orders are exact permutations and bound to the immutable packet.
Original mask field/record/source/packet identity and counts match every graph
and actual saved conformer; full accepted-producer QA inputs are exactly the
same physical family files. Original mask/z/1% report-only behavior is unchanged.

Every source keeps one graph-family and status record. This does not claim D20
success or reconstruct an unrecorded D20 call count. D20 evidence is reported as
present-valid, present-with-failed-components, unavailable/failed-or-unknown, or
interrupted-unknown. Delivered0 is not inferred scientific generation0; an
interrupted source keeps unknown count and no fabricated appendable cache.
Actual cache existence/completeness and whether at least4 canonical candidates
are already saved are reported separately. No new4+ execution is authorized.

## Storage and version outputs

The small candidate_manifest.json has status
`COMPLETE_CANDIDATE_DATASET_NOT_TRAINING_RELEASE`; actual finalizer terminal/C0
is checked outside the producer by the daily workflow. It binds dataset version
v2_candidate, PubChem/population version, source/189/QA/generation/accounting and
startup lineage, plus external catalogs for every MID/conformer/family/batch
and physical inode/bytes evidence. Large data/catalogs stay outside Git.

Logical file bytes and native allocated blocks are separate. Lossless u64
inode/device keys deduplicate actual blocks. Families, cache/packet/journal/
manifest and per-MID/batch directories are persistent variable dataset costs.
Generation SQL/progress/orphans, QA SQL/spill/output, finalizer SQL/catalog cost
and shared read-only inputs are reported separately. Shared input DATA SHA is
not falsely described as freshly reread. A cross-category shared inode suppresses
an ambiguous projection rather than being arbitrarily counted twice.

The10M linear estimate is4x only the measured persistent UFF/D variable dataset
part. It assumes the same R/N size/sparsity/compression distribution. Full-pool
NN, ranking, Common/calibration/shared inputs and QA/finalizer scratch are not
multiplied4x. This is a storage extrapolation, not a capacity guarantee, runtime
ETA or authorization to generate10M/4+ data.
