# PDBbind general27 original index evidence only

New bounded read-only Alpha protocol; not executed by its author. Exact consumer is
`python -B -m secondary_pdbbind_index27_extract_v1.run --plan PLAN --startup-proof PROOF`.
It requires independent Root source/scope approvals, fresh Alpha UID1264 proof,
16 CPUs, no requested memory/exclusive/GPU, 600 seconds, 2 GiB, current scope7,
all registered output reservations and at least200 GB effective free space.

Actual1884866 physical inventory C0 is a historical parent, not identity acceptance.
Its44510 original index relations have exactly27 general rows without native context
in **all** components. This is distinct from the12119 general rows with recorded key
UNKNOWN. The new job preserves both axes and every old error/result/source unchanged.
It cannot create or fix a molecule, compute a graph/key, fetch a structure, or release
identity/decontamination/pool/training.

Exactly three new pure methods run after fresh admission and before original DATA or
Budget creation. They cover relation/projection mass and literal binding, original
opaque line grammar, and large locator plus complete TAR/gzip/inventory boundaries.
No old B3/native3/audit3/full3 methods are reexecuted. Original source `token`,
`StrictTarInfo`, `Expanded`, CSV6 `Budget`/journal objects are imported unchanged.
Importing their modules is permitted; no claim of RDKit import absence is made.
No RDKit parser/key/kernel call is made.

Four DATA locators (combined1927276053 bytes) are derived from real producer receipts:
1884866 all_original_index_relations; 1884856 source_rows; original general payload
and its original container_inventory. DATA uses the strict positive producer triple
validator without the2 MiB SMALL ceiling. No login materializer hashes/parses DATA.
After fixtures, each original owned regular file is whole-SHA verified through a
held stable FD before any DATA decoding. The relation and old source projection
are fully consumed with duplicate-key rejection, exact source counts and complete
second-pass SHA. All44510 IDs and57480 native context events are counted; no native
body is reparsed. Only the exact27 already-recorded missing-context rows are selected.

The entire1.759 GB gzip TAR is read again through the original strict TAR classes:
every64016 member must exactly match the frozen inventory, every regular body is
SHA-verified, and the gzip is drained to EOF/CRC with the producer's exact decoded
byte count/SHA. Files are never extracted. The sole fixed index member is
`v2019-other-PL/index/INDEX_general_PL_data.2019`. Original grammar is unchanged:
only lines beginning with literal `#` are comments, each other line increments a
zero-based ordinal, and its first4 bytes are the original ID. No strip/case/zero
normalization. The selected row must match ordinal, exact ID token, original length
and whole lineSHA. No affinity, label or downstream numeric field is decoded.
The new finite1 MiB line ceiling yields HOLD, never a truncated row or silent skip.

Output DATA contains the27 original relation/projection events and input byte
segments, original full lines including EOL as opaque `.raw`, exact source ordinal/
ID/line provenance, original comment/header bytes, and frozen source/version/download
mapping. Original source labels/URLs and comments do not establish the reason for
missing structures or completeness of a release. That cause remains UNKNOWN.
Summary/receipt only expose counts, integrity and DATA references, never IDs, SMILES,
raw lines or target values. Worker logs are deliberately outside this protocol:
the old worker stream has no per-call stdout/stderr offsets for causal attribution.

Budget is the original2 GiB CSV6 object, including its existing drain reserve,
current RSS/MemAvailable/storage/wall soft STOP, natural return, and cost-report-
continue semantics. Outputs are stable append-only regular files; no transient
SQLite journal/tree race. Resource/time/error shortfall keeps all evidence prefixes
and writes PARTIAL_HOLD, never a complete27 claim. A600s allocation is a ceiling,
not an assertion that whole compressed+decoded validation will finish in time.
Root must record the new job's actual terminal cost, including failures.

Source-only metadata entry is the separate single-protocol thin package
`secondary_cpu_readonly_pdbbind27_v1.materialize`; see handoff for Root CLI.
