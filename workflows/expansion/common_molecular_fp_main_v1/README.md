## What is executable

`run.py` consumes an exact Main central-v2 plan/proof on **compute-0-13**, CPU
partition, 16 allocated CPUs, no SBATCH memory/exclusive/GPU. Its full primary
module/argv/source pins and kind/parameters/input refs are checked by the
existing `runtime.require_startup`, then by producer checks. Python3.11.14 and
original RDKit2025.09.5 apply. No UFF, QM, network, native invocation or once
ledger write is present.

The admitted parent creates a fresh artifact directory, runs exactly three new
synthetic methods, and only then creates its monitor and opens scientific DATA.
Workers use spawn, exactly16, barrier16 and at most32 pending MID tasks. They set
native-library thread counts to1. The closed receipt requires16 actual worker
PIDs with returned MID records, not just a declared worker count.
Each worker also durably writes its actual original-kernel source/function-object
proof once before the barrier; the parent verifies all16 job/PID bindings and
includes the producer-pinned small proof refs in its receipt.

`profile` is fixed512 MIDs: SHA-ranked256 from each actual Common TRAIN/VAL
role, seed20261027, without replacement. Selection uses only MID/role, never
targets, labels, derived features or downstream overlap. The entire population
and formal record census is still scanned in profile. The selected graph cohort
is not declared representative of a single unweighted whole-population mean;
Root reviews per-role population/context and actual output/cost before full.

Profile cap is2GiB, wall600..7200 whole-minute seconds. Full requires an actual
same-input512 C0 profile, unchanged current source bytes and a separate Root
cost/quality/storage review, explicit2..128GiB cap and600..172800 whole-minute
wall. These are software I/O/time bounds, not an allocation memory claim or a
proven worst-case forecast. Full has no pool, baseline1M or NN authority.

## Data path and original function reuse

After fixtures, each of33 closed bodies is opened read-only, full-SHA checked,
and held on the same FD used by Arrow. UID1278, regular/non-symlink path,
size/dev/inode/mtime/ctime and FD/path stability are checked. No old device number
from a different compute mount is silently imposed as a current frame; original
authority remains pinned, current CPU frames are separately recorded.

The scalar SQLite census ingests all16 Common parts and16 role parts. Every
true Common MID must have the same actual role/source-role/native-record count
in whole-role authority. Counts/digest must match final header TRAIN/VAL roles
and denominator minus exclusions. Duplicate MIDs fail. There is no physical
conformer scoring or invented CID: absent original CID is null.

Arrow scans the **complete** original formal Parquet in batches8192, projecting
only the literal allowlisted original identity/QC columns plus the order's
file_group. Every physical row reaches EOF; each Common MID's full record count
must equal membership. A MID repeated across segments, missing MID or wrong
count stops the job. The all-Common sorted length-prefixed MID/role digest and
role molecular/physical-record counts are recomputed and must equal membership.
No11M Python collection is made: one MID's bounded variant set, batch8192,
disk-backed scalar tables and32 tasks are retained.

For selected MIDs, every original row's source graph/key/provenance/accepted-QC
evidence is durably fsynced before its task is dispatched. The actual existing
candidate objects are used:

- `selection.select` chooses original creator's `smiles.strip()` entrance.
- `worker.load_kernel/derive` call the original frozen
  `features_legacy_compatible_v2.features_candidate` function object and existing
  source proof, with original screen success passthrough and only its already
  isolated exact ring-Kekulize fallback.
- `projection.reduce_variants` preserves all derived graph/key variants and
  accepts strict5 only for one canonical isomeric graph/full-key pair and equal
  actual feature values. It adds no stored/reidentified/WP5 equality gate.
- `census.Census` supplies the existing sorted MID/role/record contract.

No fingerprints, descriptors, key algorithms, neutralization, stereo/isotope
stripping or repair are reimplemented. Chemical reasons/technical errors become
retained unresolved evidence for the existing Common MID, not new exclusions.
Finite4096 variants/MID,1MiB per source string and4MiB total variant text cause
technical HOLD with retained original evidence; they do not remove a molecule.

Each returned graph result is durably written before the MID summary and any
derived projection. Rich results are individually recorded, so the summary
does not duplicate an arbitrarily large all-variant list in one JSON container.
Ordinary source/results are never overwritten. Errors preserve prefixes; no
automatic retry or signal is sent. Unknown/conflicting MIDs make the audit HOLD
and prevent complete reference publication.

Strict5 JSONL is emitted in sorted MID order from the new scalar index only
after results are durable. It contains exactly:

```
molecule_id, full_key, ecfp4_2048_hex, generic_murcko, generic_ring_systems
```

Two MIDs sharing a graph/key remain two rows. Empty acyclic Murcko stays `""`;
native ring lists stay intact. The old consumer's set-presence ring frequency
and ECFP4/radius2/2048/chiralityFalse math are unchanged. Every output journal is
independently whole-SHA read back; strict5 is parsed on that same FD and its
exact fields, sorted uniqueness and MID/role/native-record census are checked.
The scalar SQLite is closed before its producer SHA is observed; no active
SQLite is read/hash accepted.
