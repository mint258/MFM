## Real tables and bounded stages

Every build emits typed Parquet:

- `geometries`: the seven existing D5 geometry columns plus actual float64 coordinates, native atomic numbers, SHA, source physical pointers, energy and provenance. Ordinary bases have null parent/view. PM7 whole-LMDB byte/SHA columns deliberately remain null; the per-record pointer/payload authority is retained in DATA.
- `orders`: `molecule_id,geometry_source,order_type,method,rank,geometry_id`; method equals order_type exactly. All three permutations/rank0 are produced by the original function objects.
- `atom_counts`: actual `(geometry_id,n_atoms)` for every ordinary base, without deriving N from element sets.
- `audit_identity`: original physical namespaces serialized as `physical_identity_json`, only accepted original S′ or data_v1_fill task/seed/candidate. This closes the existing P′ preparer's explicit identity-table seam for V3 dispatch ledgers, without modifying its old legacy-ledger validator.
- `roster`: exact frozen logical molecule ordinals and two-source/child counts.

`prepare` hashes the real16 Common membership +32 physical maps, canonical population, current-owner and HOF catalogue DATA on CPU. It creates a disk-backed whole true-Common roster, sorted by molecule_id, and verifies physical/native record equality and original N. It opens no packet, LMDB or child body. Fixed `logical_partition_molecules` (explicit Root integer1..512) is frozen before CPU and does not depend on allocation/worker count. Each range gets a scientific JSONL descriptor and a small locator manifest with actual source triples. Registry pages hold up to512 small range-manifest refs; login reads only these operational pages, never descriptors to discover sources. This avoids treating a large DATA locator as a <=2MiB source JSON or placing every population packet in one metadata request.

The first real pilot uses purpose `pilot512`, partition512, logical range `[0,512]`, with all original conformers for those512 true Common molecules. A smaller old pilot is not equivalent. `base` starts16 spawn workers/at most32 pending tasks, preserves every original ordinary physical row, computes three actual source orders, retains complete lossless molecule packets and writes the five typed tables. Complete per-record/source failures remain DATA; incomplete orders or exceptions cause HOLD and prevent release. No valid label is deleted or reclassified.

`verify` reads every typed field/schema/geometry/atom SHA, every source packet bit/type (for a leaf), bidirectional actual Common physical keys, native atom counts, explicit child-parent keys and every original three-order permutation. It rereads one original native record per molecule to recover the actual fixed-map source graph; then16 bounded workers recompute all three orders with the original Kabsch object. It streams source IDs and aggregates counts, not a population-sized Python molecule list. The whole-Common flag requires the exact complete interval and both-way equality to every true Common MID. Pilot/partial tables cannot assert it. Inherited full readback chains preserve the source-to-table bit comparisons through merges.

Only an actual512 verification C0 plus independent `ROOT_D5_INPUTS_ACTUAL512_REVIEW_V1`/`APPROVED_EXACT_ORDINARY_SOURCE_PARITY` review enables purpose `full`. The review binds `pilot_closure_references` (receipt/startup_proof/accounting), same Common and `all_original_quality_gates_unchanged=true`. It cannot use a Source fixture, old profile or timed-out parent as C0. Full source ranges may use a newly frozen smaller logical partition to keep each exact request bounded, retaining all members and original science. Partitions are not changed dynamically to discard a difficult molecule.

`merge` accepts at most32 actual C0/readback-complete adjacent intervals with the same table domain; no overlap, hole or duplicate is accepted. It concatenates original typed streams in interval order, then requires its own actual independent `verify`. Repeat bounded merges through existing Root central submissions until full coverage. No new controller/queue or auto submission exists. Output storage layout/merge grouping does not change any per-molecule scientific order. The outer receipts require Root review and never self-sign D5.
