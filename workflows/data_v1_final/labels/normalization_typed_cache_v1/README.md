# Final-TRAIN typed-cache interfaces: source candidate

SOURCE ONLY. This package implements the small candidate/authority contract,
fixed logical ordering, D4-specific disk locator library, and pure conversion
from exact typed-cache rows into the existing normalization reader's
`(owner, atomic_numbers, entries)` output shape. It does not implement or
register a runnable production fit stage. There is no new queue/controller,
publisher, native invocation, scientific retry, mask rule, or normalization
publication command. No child Python/AST/tests/DATA/SSH/Slurm execution is claimed.

The candidate helper always returns `NONEXECUTABLE_CANDIDATE_INTERFACES_ONLY`,
even when all reference names are supplied. References do not prove contents.
Current source snapshots, the real512 profile and old1904 TIMEOUT cannot fill
missing final authorities. Future producer references/hashes are never made up.

## Root metadata CLI (small metadata and SOURCE only)

After integrating and actually checking the source package on an allocated
CPU, Root may use the established Main Python/PYTHONPATH:

```text
PY -B -m workflows.data_v1_final.labels.normalization_typed_cache_v1.metadata
  --request ACTUAL_SMALL_ROOT_REQUEST --output NEW_CONTROL_DIRECTORY
```

Request schema is `ROOT_D4_TYPED_CACHE_CANDIDATE_REQUEST_V1`, with optional
`parent_references` containing only actual `path/bytes/sha256` triples named by
`contract.FINAL_PARENTS`. An empty parent map is legal and reports every missing
dependency. The helper opens no reference target/DATA body. It reads the small
request and this package's SOURCE files and writes a fresh candidate receipt.
It signs no release and generates no queue request, stage specification or job.

## Independent final authority and recovered origins

`contract.validate_release` checks the normalized **Root review summary**
`ROOT_D4_TYPED_CACHE_FINAL_INPUT_RELEASE_V1`, not a replacement for actual CPU
validation of producer contents. The explicit final references are coverage,
parts inventory, matched full-TRAIN calibration, final mask release, registry,
field map, physical mapping, owner authority, Common, ROUTINE roles,
geometry map/order, exact diagnostic base/target exclusion, fixed logical
statistics, native-semantics review and current Root resource review.

The recovery producer is SB2's separately frozen
`LABELS_RECOVERED_FULL_SOURCE_COVERAGE_V1`, whose status stays
`FULL_NUMERIC_SOURCE_COVERAGE_OBSERVED_NOT_FINAL_MASKS`. Its own final-mask/D4
release flags remain false. Exact accepted origins have two literal types:

- `ACTUAL_C0_BATCH`: a genuinely new registered producer C0 and complete
  manifest/window/part/startup/request/submission/accounting/raw evidence.
- `TIMEOUT_ADOPTED_CLOSED_WINDOWS`: old1904 remains TIMEOUT; independently
  approved exact windows require inventory C0, seed C0 and Root selection,
  resource and complete parent-chain reviews. Adoption is not old producer C0.

The Root summary pins each detailed chain and the actual frozen parts
inventory. Unknown/held consumed ranges, unverified parts, gaps, duplicates or
quality HOLD prevent final input acceptance. No old book is opened to select
windows, no adopted part is rewritten, and no unavailable origin is retried.
The recovered cache's complete physical/canonical/role coverage is necessary
but cannot self-sign full-TRAIN calibration, final masks or D4.

The fixed masses in this version describe the original PM7 P/D cache only:
2208 sources;11231854 canonical records;14 task slots plus independent base;
157254650 physical label rows and11232475 base rows, including separate
8694 label and621 base noncanonical differences. They are not Pprime counts.
This interface explicitly rejects using these PM7 cache rows as UFF Pprime.
Independent Pprime numerical inputs and statistics remain pending.

## Mathematical bindings and order

`bindings.py` imports real original objects: projection decode/at, cache-v1
projected_decode/entries (through the existing cache-v2 narrow base fix), the
original profile's identical TSQR/radix/entry kernels, and original
calibration/series/moments. `verify_function_objects` tests identity; no
function body, original module global or native engine is monkeypatched.

Logical partitions are frozen original owner source-job groups, with the
original dataset/group/file sequence followed by source physical row and
unchanged registered field/native leaf order. Physical cache filenames,
part boundaries, arrival order, allocation and worker identity are absent
from the numerical order key. `TSQR.chunk=256` is the actual frozen source
default; the original ordered left-fold QR and Chan reductions remain.
No balanced reduction tree, rcond/element-basis change or new tolerance is
introduced. The original rank/degenerate/no-value/constant/zero-std behavior
and q.001/q.999 statistic-only winsorization remain original function behavior.

`ordering.logical_manifest` requires the actual original group plan and exact
ordered source references; it does not infer group order from a cache listing.
`index.LocatorIndex` stores each owner and part reference once, with a strict
canonical `(record_ordinal,task)` key and original physical locator. It is a
D4-specific disk index, not another science-value export or general data layer.
Its page ceiling does not bound journals/admin by itself: the future CPU
wrapper must charge all those bytes to a fresh whole-output/spill envelope.
No full index size/performance is claimed without the actual bounded probe.

`reader.base_numbers` reuses the existing Z-only metadata projection and
validates actual ordinal/record, payload SHA, fixed atom order, heavy count
and original PM7 geometry status. `reader.observation` reuses original logical
CELL reconstruction, component pointer/type/bit/owned-index checks and candidate
mask regeneration. It then requires final source/new/validity/leaf parity;
calibration-only review codes may differ and are carried separately. A genuine
final validity change requires a new explicitly reviewed overlay/version,
not a switch to suppress parity. No values are clipped, reindexed, merged,
averaged, rotated or cast to float32 by this adapter.

## Deliberately unimplemented execution seams

SB2's recovery source is not frozen at this handoff. This package therefore
does not guess its detailed inventory parser. A future small CPU preparation
must consume that exact DATA inventory, validate every accepted origin and
current part frame/whole SHA as required, join the actual owner/formal metadata
and final masks, and feed `validate_locator`/`LocatorIndex`. The canonical
9-column SQLite lacks formal payload SHA and heavy count; those columns must
come from their genuine existing formal authority, never invented hashes or
an extra whole-LMDB requirement. No original LMDB is required for this join.

The CPU preparation/reader IO wrapper, existing normalization worker/run import
binding, actual finite no_mem resource stage and independent original-Parquet
replay remain later integration work. They must be in the original central-v2
queue,16CPU/CPU-only/no requested Slurm memory, finite<=48h, fresh same-storage/
UID/proof,200GB account headroom, whole output/spill and RSS/MemAvailable natural
drain guards. These interfaces are not permission to run an unregistered driver.
Do not call old normalization runtime under no_mem: it still requires an actual
64GiB requested allocation. Do not copy or weaken that old guard.

Before real DATA, Root must actually run the three new synthetic boundaries
and object/source-closure proof in a real allocation; no PASS is asserted here.
Those boundaries target the new mixed-origin release, exact locator/fit-side
semantics and numerical order across physical repacking. They do not rerun
the old6/24 fixture suites or replace actual full cache/QA/native-frame evidence.

Final native frame/origin/precision, r73 dual-end basis-channel/onsite domain,
r674 exact six-component tensor, real child geometries/atom ordering and
unit/sign conventions still require actual D1/registry review. Raw ordered
leaf preservation is not proof of basis invariance or model normalization.
No final Common/TRAIN/diagnostic/Pprime/D4 acceptance is asserted.
