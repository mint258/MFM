# 测试与验证标准

用户发现执行 agent 容易过度检查、拖慢开发。原则是：该验的地方验一次，其他地方不加检查。

## 1. 只在这些位置验证

可能悄悄破坏科学结论的地方：

- 标签值和单位；
- 分子 / 构象 / 原子 ID 与几何、标签的对齐，源原子顺序；
- 划分和泄漏（TRAIN 与下游测试集按完整 InChIKey 的重叠）；
- checkpoint 与实验条件的对应；
- 新预测头或新目标的数值正确性、标签约束是否真的成立。

其余一律不加检查，不写收据，不做哈希包。

## 2. 一次验证，由产出者做

- 每个产物由生成它的步骤验证一次。
- 除非检查失败，不做独立复核、不做二次回读、不重复测吞吐。
- 单元测试通过后，不再用另一种方式重复检查同一逻辑。

## 3. 真实使用就是验收

- 数据交付：模型线的真实 loader 加逐头过拟合测试；只有在那里出问题才回查数据。
- 新臂：真实训练本身 + R1/R3 读出就是验收，不另建验收。
- 新预测头：真实 loader 取少量 TRAIN 样本、冻结编码器只训新头（例：64 样本、最多 2000 步，loss 降到初值 1% 以下）。如果头复用了已收敛的参数、这个门槛不适用，就直接正式训练，不硬套。
- 基线环境：在固定的少量下游分子上跑通推断即验收。

## 4. 单元测试与回归

- 单元测试只覆盖新逻辑，常见三类：新开关关闭时与原实现逐位一致；新模块输出维度和 padding 排除正确；关键约束成立（如门恒为 1、两字段共享参数）。
- 新代码一律放在默认关闭的开关后面，不改既有配置文件。
- **完整回归只在合并前跑一次**（仓库默认测试 + `python tools/check_repository.py`），不是每次改动后都跑。
- 回归里的历史失败（依赖服务器文件、真实 Slurm/cgroup、旧部署绑定）如实记录，不为了全绿去改检查器、删历史资产或反复重跑。
- CPU 测试也走 CPU 节点（compute-0-8~19）的真实分配。

## 5. 数值阈值的写法

- 每个阈值同时给绝对和相对容差，或给范数相对误差，并说明已计入数值噪声。
- 例：逐字段损失 |Δ| ≤ 10·ε_loss + 10·ε_loss·|loss|；整模型梯度相对 L2 差 ≤ 10·ε_grad；ε 是基线在同卡上跑两遍得到的噪声底。
- 精度门：FP64 相对 ≤ 1e-9 是硬门；FP32 结果只作非阻塞诊断。

## 6. 性能改动的验收（提速线方法）

- **A 类**（不应改变任何数值）：固定 20 个 batch、两组权重的单步前反向，逐字段损失和完整梯度与基线逐位一致；1000 个 batch 的分子 / 构象序列和 RNG 逐批一致。做不到逐位一致就按 B 类处理。
- **B 类**（会改变浮点求和顺序）：先测噪声底，再按第 5 节的门槛比单步；再做短训练检查（同初始化同 seed 训练 ≤1000 次更新，两边都无 NaN/Inf，最后 200 次更新的平均损失 |差| ≤ 0.01 + 3% × 基线）。不训练更多步，不做下游评价。
- 测速：100 步预热 + 1000 步计时，记录样本/秒、主进程 CPU%、整卡平均功耗、CUDA 峰值。为抵消系统漂移，按 **基线 → 候选 → 候选 → 基线（ABBA）** 在同一张卡上连续测；提速倍数 = 两次候选均值 ÷ 两次基线均值；"有效"要求倍数 ≥ 1.05 且提速幅度大于两次基线差距的 2 倍。
- 只测了一种卡型时注明。是否在正式运行中启用开关由用户决定；在跑的运行不切换。
