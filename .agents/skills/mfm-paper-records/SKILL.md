# 论文素材留档

## 1. 每份任务书都要求的留档

用户要求：**每份交给 Codex 的指南都必须要求把显著性分析和数据处理方法写进仓库**，供以后写论文。具体是：

- 每完成一个阶段，在 `docs/<line>/` 写一份文档并推送，内容写到可以直接用于论文方法部分：
  - 方法与定义（改了什么、基底是什么、配置键）；
  - 数据处理步骤（样本集、划分、过滤、归一化、剔除清单）；
  - 显著性分析：bootstrap 单位和次数、seed、配对方式、CI 的含义、判定规则和门槛、是否做了多重比较校正；
  - 结果（Δ、CI、判定）与每个测试是怎么来的（由哪个诊断或假设引出）；
  - 局限。
- 线的最终报告（如 `docs/p_heads/REPORT.md`、`docs/p_followup/FINAL_REPORT.md`）汇总每臂的 Δ、CI、判定、方法和局限，并写清哪些是转录已发布结果、没有重算。
- 规则文件（任务书、补充指示、预注册）本身也是论文素材的一部分，保留不删。

## 2. 发现记录

重要的观测写成 `docs/findings/<主题>_<YYYYMMDD>.md`，从 main 分出 `docs/finding-<主题>-<日期>` 分支提交。范例：`docs/findings/LAST_LAYER_COLLAPSE_20261115.md`。结构：

1. 记录日期、状态（例："已观测，单种子，机制待某实验证实或证伪"）、适用范围（原始观测，不是已验证结论）。
2. 结论（一段话 + 编号的独立证据）。
3. 实验设置表。
4. 各项证据，表格附数据，每节末尾列"要点"。
5. 排除的替代解释。
6. 机制解释（标为假说）。
7. 相关工作（标注"写作时需核对原文"）。
8. 可证伪的预测（下一轮哪个臂、应看到什么、看不到时怎么修正）。
9. 局限（种子数、训练条件、因果性未建立等）。
10. 数据来源（分支 + 文件路径）。

## 3. 目录分工

| 目录 | 谁写 |
| --- | --- |
| `docs/<line>/` | 该线执行窗口 |
| `docs/findings/` | Claude 与用户（可由执行线提供数据） |
| `docs/paper/` | 只由用户和 Claude 更新；执行窗口不修改 |
| `docs/references/` | 文献地图（PR #9） |

## 4. 写法

- 数字从产出文件转录，注明来源路径；不在报告里手算新统计。
- TIE 写"无显著改善"，不写"等价"。
- 单种子、未完成、被用户取消的结果要显式标注及依据。
- 范围变化要如实披露（例：暂缓的 5 个下游终点，论文里要按适当方式说明，内部不公开的登记表不能代替公开的方法说明）。
- 文献引用在写作时核对原文，不凭记忆写细节。
