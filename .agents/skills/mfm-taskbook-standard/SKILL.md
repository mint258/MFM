# 分支任务配置标准

模板见 [references/taskbook-template.md](references/taskbook-template.md)。

## 1. 两类文件

| 文件 | 路径 | 用途 |
| --- | --- | --- |
| 任务书 | `docs/<line>/TASKBOOK[_Vn].md` | 一条线的完整授权：做什么、怎么判定、什么时候停。修订在文末"修订记录"追加一行 |
| 补充指示 | `docs/<line>/USER_DIRECTIVE_YYYYMMDD[B].md` | 用户中途的决定。开头写"适用：…本指示覆盖任务书中与之冲突的条款，其余规则不变"。被后来的指示取代的段落，加一行引用说明指向新文件 |

指示里的机器可读部分同步到 `configs/<line>/`（如 `user_directive_20261117.json`、`preregistration.json`）。

## 2. 任务书必备章节

1. 标题、日期、状态、授权来源；与哪些在跑的线并行，以及**不改变**它们的哪些臂、预算和判定。
2. 给执行者的首要规则（先读）：不过度防御；只训练列出的运行；尽量复用已有结果；不做本书没有的任务（新想法在日报末尾记一行，不执行）；每完成一个阶段就推送。
3. 背景与已有结论：直接引用，并列出"已有结果：直接复用，不重算"表（内容、位置、本书用法）。
4. 组织方式：协调窗口和子 agent 各自负责什么、改动范围（目录），并写明并行原则：没有科学依赖的工作之间没有先后顺序，谁先就绪谁先上卡。
5. 总规则（见第 3 节）。
6. 各部分的具体臂：每个臂相对基底只改一处，写明"回答什么问题"；配置由基底 JSON 复制，只改列出的键。
7. 预注册的判定规则和结果解读表（看到结果之前写入 `configs/<line>/preregistration.json`，之后不改）。
8. 资源与排程：运行数、GPU-h 估计、上卡优先顺序。
9. 产出：每份文档写明方法、数据处理、显著性分析、结果、局限。
10. 不做清单。
11. 真正的停止条件。
12. 报告与 GitHub。
13. 修订记录。

## 3. 总规则（每份任务书都要写进去）

这些是用户要求每份指南都遵守的原则：

- **只在可能悄悄破坏科学结论的地方验证**：标签值、ID/几何/标签对齐、划分和泄漏、checkpoint 与条件的对应、新头的数值正确性。
- **每个产物只由产出它的步骤验证一次**；除非检查失败，不做独立复核或二次回读。
- **真实下游使用就是验收**（例如真实 loader + 逐头过拟合测试、真实训练 + R1/R3），不重复建验收。
- **只预注册科学决定**，不预注册工程检查。
- **每个数值阈值都同时给绝对和相对容差**（或范数相对误差），并考虑数值噪声。
- **单元测试只覆盖新逻辑**；合并前跑一次完整回归，不是每次改动后都跑。
- **基础设施故障**：直接修好重跑，训练从最近的完整 checkpoint 续接，不单独报告。
- **时间盒**（2026-11-25 修订，全文见 `docs/interfaces/TIMEBOX_RULE_20261125.md`）：工程失败（参数/接口、路径、额度与 storage guard、调度准入、drain、进程竞态、OOM）修好重跑，不计次数、不得标 UNRESOLVED；只对同一根因的科学或方法失败计数，修复 2 次后仍失败或诊断修复累计超过 4 小时（不含排队和计算）才标 UNRESOLVED，取保守默认（写明默认是什么，例如"该臂记为缺失 / 按未胜出处理 / 退回原头"），主线继续。额度不足先释放已结束任务的未用 future，仍不够写"待用户决定"并等待，不算失败。
- **成本**超过估计的 1.5 倍不是停止条件：报告后继续工作。
- 集群规则照 AGENTS.md 现行规则执行（见 `mfm-cluster-operations`）。不停止、不抢占、不改动其他线在跑的任务。

## 4. 停止条件

只列真正的停止条件；其余一律"日报记一行，继续"。全项目通用的四条：

1. 需要删除文件（本任务自身 scratch 以外）；
2. 需要改变科学规则或标签定义（包括 mask、归一化参数、字段集合、判定规则）；
3. 需要使用学校付费服务器；
4. 需要正式预训练。

线特有的可以加，例如"需要启动本书列出之外的训练或任何 9M"、"需要把本书改动接入主线的在跑运行"。确认阶段（如 9M）属于既定阶段，不算正式预训练。排队等资源不是停止条件。

## 5. 不做清单（每份都要有）

常见条目，按需选用：

- 不加本书之外的臂，不扫超参（只用写定的一个值）。
- 不跑第 3 个种子，不在补种子规则之外补跑。
- 不停止、不迁移在跑的训练（用户对某条明确下了停止指令的除外）。
- 不改其他线的分支和文件；不改 `docs/paper/`。
- 不改归一化、字段定义、判定规则。
- 不对已有结果做二次读回或独立复核。
- 不根据结果回改任务名单、划分或判定口径。
- 不使用付费服务器，不申请 exclusive，不删除文件。
- 结项后不再占用 GPU。

写"不做"时可以附一句理由或已有证据（例："不把 xTB 目标改成 xTB − PM7 差值：思路同第 1 轮 A2，A2 是最差的臂"）。

## 6. 报告

- 每天一份日报，最多一页；同一天更新同一个文件。写实际结果、未完成事项、下一步，以及"待用户决定"。
- 每周一次成本账（真实 Slurm 记录 / GPU-h）。
- 收据和 SHA 只给最终交付物。
- 里程碑（预注册、每臂训练完成、判定、CURRENT_BEST 更新、冻结、最终报告）发生时各推送一次。
- 写论文要用的方法和显著性分析写进 `docs/<line>/`（见 `mfm-paper-records`）。

## 7. 用户长时间不看进度时

用户会预先写一份"收尾 / 交接"指示，把这期间的决定一次写定（例：p-recipe 11-18B）。这类指示要写明：自动决定的规则、冻结条件、不能完成的臂怎么处理（按未胜出处理，不等待）、结项动作（最终报告、完整回归、仓库检查、开 PR 但不合并）。执行中不再等待用户确认。
